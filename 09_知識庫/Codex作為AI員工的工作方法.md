# Codex 作為 AI 員工的工作方法

來源：學長 Ethan 影片「Codex保姆級完整教學：從入門到進階，自動生成內容、網頁、影片和App，快速學會指揮你的超級AI Agent」

## 核心觀念

Codex 的價值不是「回答問題」，而是進入本地工作流，讀文件、改文件、整理資料、串接工具並交付結果。對 Ewalk.ai 來說，阿順應該被設計成一位熟悉公司規則的 AI 工作夥伴，而不是每次都從零開始理解任務。

## 對阿順有用的重點

### 1. 專案要有入職手冊

影片中最值得採用的是 `AGENTS.md` 概念。這份文件等於阿順進入專案前的工作規則，應包含：

- Ewalk.ai 是誰、主要服務什麼客戶
- Vault 的資料夾分工
- 輸出語言、語氣與格式
- 做事前後要如何回報
- 什麼內容要抽成 SOP、Prompt、案例或知識

這可以降低每次交辦時的重複說明成本，也讓阿順在整理檔案時更穩定。

### 2. 把重複工作變成 Skill / SOP

影片強調 Skill 是把一整套標準化流程固定下來。Ewalk.ai 目前最適合優先 Skill 化的工作：

- 語音筆記整理
- 每週內容產出
- 月報產出
- 廣告上線檢查
- 客戶品牌資料整理
- IG 圖文與 Reels 腳本生成
- 客戶會議後的任務拆解

目前 Vault 已經有 `13_SOP流程` 與 `11_Prompt資料庫`，後續可以把常用流程從「文件」再提升成可直接呼叫的 Skill。

### 3. 用外掛接工具，用 SOP 控品質

影片提到 Gmail、Google Calendar、Google Drive、Canva、Figma、簡報、試算表等外掛。對 Ewalk.ai 的實用方向是：

- Google Calendar：自動整理行程、提醒客戶會議、找空檔
- Google Drive：素材歸檔、簡報與交付物查找
- Spreadsheets：月報數據整理、廣告成效表
- Presentations：提案簡報、課程簡報、月報簡報
- Browser / Computer Use：檢查網站、後台、設計工具或交付頁面

原則是：外掛負責「接觸工具」，SOP 負責「交付品質」。

### 4. 並行任務要拆清楚

影片示範多個任務背景執行。Ewalk.ai 可以採用這種拆法：

- 一條線整理客戶資料
- 一條線產出內容腳本
- 一條線檢查廣告 / 月報數據
- 一條線把產出沉澱成 SOP 或案例

並行前要先切清楚每條線的輸入、輸出與資料夾，避免內容互相覆蓋。

### 5. 每週回頭優化阿順本身

影片提到可以定期回顧工作歷程，優化 `AGENTS.md` 或 Skill。這很適合 Ewalk.ai：

- 每週檢查收件匣、語音轉錄、客戶待辦
- 抽出新的 SOP、Prompt、案例
- 更新阿順交辦規則
- 補強常出錯的命名、分類、輸出格式

這會讓阿順越用越貼近 Ewalk.ai 的實際工作方式。

## 可直接採用的阿順指令句型

```text
請先讀取 AGENTS.md、Ewalk.ai Brain/README.md 和相關客戶 README，再開始整理。
```

```text
請把這份資料整理成 Obsidian 筆記，並判斷它應該放到收件匣、客戶資料、SOP、知識庫、案例庫或 Prompt 資料庫。
```

```text
請完成任務後告訴我：你新增/修改了哪些文件、放在哪裡、下一步建議是什麼。
```

```text
如果這次工作有可重複使用的流程，請順手抽成 SOP 或 Prompt 草稿。
```

## 對 Ewalk.ai 的下一步

- 已新增根目錄 `AGENTS.md`，讓阿順進入專案時有統一工作規則。
- 建議把「語音整理」「月報」「每週內容」「客戶啟動」優先升級成更完整的 Skill。
- 建議每週固定做一次阿順自我優化：清收件匣、抽 SOP、更新 Prompt、補案例。
