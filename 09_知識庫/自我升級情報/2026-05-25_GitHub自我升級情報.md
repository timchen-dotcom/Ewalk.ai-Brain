### 2) GitHub Agentic Workflows（gh-aw）：把「允許工具清單」與「版本鎖定」做成可審計的 Agent 工作流底座

- 來源標題：GitHub Agentic Workflows — AI Engines / Releases and Versioning / Creating Workflows（近 7 天內文件持續更新）
- 來源連結：
  - https://github.github.com/gh-aw/reference/engines/
  - https://github.github.com/gh-aw/reference/releases/
  - https://github.github.com/gh-aw/setup/creating-workflows/
- 相關工具標籤：#Codex #ClaudeCode #Gemini #工作流 #自動化 #權限治理
- 重點摘要：
  - 同一套 agentic workflow 可以指定不同 engine（含 Codex / Claude Code / Gemini CLI），用一致的方式在 CI/本地跑。
  - 版本治理是兩層：`gh aw`（工具）與 `.lock.yml`（編譯後的可執行工作流）；並且 lock 檔會把 Actions pin 到 commit SHA，降低供應鏈風險。
  - 權限/工具管控的細節（如允許工具清單、MCP allowlist、以及不小心放寬到 unrestricted bash 的風險）值得拿來當我們的內部標準參考。
- 對 Ewalk.ai 的白話幫助：
  - 我們現在做「每日自我升級情報」其實就是一種 agentic workflow。gh-aw 提供的是一套更像 CI 的治理方法：可重現、可稽核、可 pin 版本、可限制工具，對提姆先生把關會更安心。
- 建議狀態：先觀察（先做 1 次「小範圍 PoC：只跑每日自我升級情報」；不擴大到全系統）

### 3) `raine/workmux`（高度討論 Repo）：用 git worktrees + tmux 把多 Agent 並行變成可控、可回收的「任務分身」

- 來源標題：raine/workmux — Parallel development in tmux with git worktrees（近 7 天內文件更新/被引用）
- 來源連結：
  - https://github.com/raine/workmux
  - https://workmux.raine.dev/guide/
- 相關工具標籤：#Codex #ClaudeCode #工作流 #自動化 #高度討論Repo
- 熱度 / 討論理由（Repo）：
  - 核心問題命中我們的痛點：多 agent 並行時，最怕在同一 working tree 打架；workmux 用 worktree 隔離，降低衝突與上下文污染。
  - 直接把「prompt」與「選 agent」整合到 worktree 生命週期，且支援跳過昂貴 setup（適合不同任務類型的成本控管）。
- 重點摘要：
  - 每個任務一個 worktree + 一個 tmux window（更符合「任務＝交付單位」）。
  - 支援 prompt from file / prompt editor / 指定 agent；也支援把未提交變更搬到新 worktree（降低臨時任務打斷成本）。
- 對 Ewalk.ai 的白話幫助：
  - 阿順要同時追「客戶交付、內容產製、自動化修補」時，最容易「互相污染」。用 worktree 把任務隔離後，能把「同時並行」變成可追蹤、可回退、可結案。
- 建議狀態：先觀察（先在內部工程/自動化 repo 試跑；不要直接推到所有人）
