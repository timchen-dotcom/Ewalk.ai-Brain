### 1) Claude Code 2.1.143：插件相依性、成本預估、背景工作流修正

- 來源標題：Changelog - Claude Code Docs（2.1.143）
- 來源連結：https://code.claude.com/docs/en/changelog
- 相關工具標籤：`Claude Code` `CLI工作流` `Plugins` `Background sessions` `成本/Token估算`
- 重點摘要：
  - 新增 plugin 相依性治理：停用/啟用 plugin 會檢查依賴並提示可「連鎖停用」順序，避免把環境弄壞。
  - `/plugin` marketplace 瀏覽時顯示 projected context cost（每回合、每次 invocation 的 token 估算），讓「用外掛/工具」的成本更可控。
  - 背景工作/`/bg` 行為與多項 bug fix（含 worktree cleanup 保護、背景模型/effort 維持、hook loop cap 等），偏向「長任務穩定性」。
- 對 Ewalk.ai 的白話幫助：
  - 我們在做長任務（例如：自動化產檔、批次改稿、批次產素材）最怕「背景 session 跑飛」或「工具成本失控」；這版主要在補穩定性與成本可視化，降低踩雷機率。
  - plugin 相依性治理，等同把「外掛/工作流的依賴關係」變得可被管理，適合我們後續把常用工作流做成標準插件/技能包。
- 建議狀態：可升級（以「最小回歸」驗證長任務/背景 session 與 plugins 互動為主）

### 2) Gemini CLI v0.44.0-nightly（2026-05-15）：MCP 網路/Proxy、Sandbox 修正、RAG debug 記錄

- 來源標題：Releases · google-gemini/gemini-cli（v0.44.0-nightly.20260515…）
- 來源連結：https://github.com/google-gemini/gemini-cli/releases
- 相關工具標籤：`Gemini` `CLI工作流` `MCP` `Proxy/NO_PROXY` `Sandbox` `RAG`
- 重點摘要：
  - 新增：把 RAG snippets 暴露到本地 log，方便 debug「檢索到底回了什麼」。
  - 修正：network-based MCP servers 尊重 `NO_PROXY`、Proxy 支援修復（https-proxy-agent 外部化）。
  - 修正：Sandbox 在特定 distro（含 NixOS 等）permission denied、file parsing 與 EISDIR 問題。
  - 修正：企業 gateway 認證衝突、依賴漏洞更新等。
- 對 Ewalk.ai 的白話幫助：
  - 我們之後若把更多「內部知識庫/素材庫」接成 MCP 或 RAG，最常卡的不是模型，而是「網路代理、權限、路徑/檔案例外」；這版剛好針對這些痛點補洞。
  - RAG snippets 寫進 log 很重要：等於讓「檢索品質」可被稽核，方便我們做月報/交付時的追溯。
- 建議狀態：可升級（優先驗證 MCP 在代理/無代理環境的行為是否更穩）

### 5) 高度討論 repo：`rohitg00/agentmemory`（給 coding agents 的持久化記憶層）

- 來源標題：rohitg00/agentmemory
- 來源連結：https://github.com/rohitg00/agentmemory
- 相關工具標籤：`Codex` `Claude Code` `Gemini` `Memory` `RAG` `跨 session`
- Repo 熱度/討論理由：
  - repo 內直接標示 agentmemory 約 53k ⭐，且定位是「給多種 coding agents 的 memory layer + MCP server」，屬於目前社群最常見的痛點解法之一（跨 session 不必重講）。
- 重點摘要：
  - 核心解法是把「偏好、決策、流程、每日 log」以本地儲存方式累積，並提供檢索/融合（BM25 + vector + graph 之類）讓 agent 可回憶。
  - 目標場景：跨 Codex/Claude/Gemini 的長期專案，降低重複解釋與重複犯錯。
- 對 Ewalk.ai 的白話幫助：
  - 這類記憶層若設計得好，會直接提升「交付一致性」（例如：同一客戶的口吻、同一品牌的禁用詞、同一 SOP 的固定步驟），也能降低 token 成本（因為不用每次把大規則塞回 prompt）。
  - 但同時也有風險：記憶一旦寫入錯誤或被污染，會長期影響輸出品質；需要配套的「記憶寫入審核/回滾」治理。
- 建議狀態：先觀察（建議先做最小 PoC：只存「偏好/禁則/術語表」且人工審核寫入）
