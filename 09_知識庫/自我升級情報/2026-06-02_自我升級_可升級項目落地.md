## 可吸收重點

### A) Codex v0.135.0：把環境診斷與常駐狀態納入升級驗收

- `codex doctor` 的價值不只在「能跑」，而是要能留下 app-server / thread / 環境狀態，方便自動化故障定位。
- 若版本涉及 memory runtime state 遷移，升級後要驗證 thread/resume/search 類功能沒有壞，避免記憶狀態遷移後才在正式任務出錯。
- TUI 的表格與多行清單可讀性，應放進「Obsidian 交接紀錄可讀」檢查，不只看功能有沒有跑完。

### B) 記憶層候選：先比較治理模型，不直接導入工具

- TencentDB-Agent-Memory 的可吸收重點是「白盒、可追溯、分層記憶」：適合做公司交付與風險控管。
- rohitg00/agentmemory 的可吸收重點是「跨 agent 的 MCP / hooks / skills 封裝」：適合研究 Codex、Claude Code、Gemini 共用記憶的管理方式。
- 今日不做安裝；先把兩者納入既有 AgentMemory PoC 的候選評估，避免重複開新流程。

### C) Gemini headless / CI 安全：把事故變成導入底線

- 任何 agentic CLI 進入 headless / GitHub Actions / CI 前，都必須先確認 workspace trust、secrets 隔離、允許工具清單與版本下限。
- 外部 PR / issue / comment 屬於不可信輸入；不能讓這些內容直接影響工具執行或讀取 secrets。
