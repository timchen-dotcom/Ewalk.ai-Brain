### 1) CLI Agent Orchestrator (CAO)：把多個 coding CLI（Codex / Claude Code / Gemini）用 tmux + MCP 編排起來（高度討論 Repo）

- 來源標題：awslabs/cli-agent-orchestrator
- 來源連結：https://github.com/awslabs/cli-agent-orchestrator
- 相關工具標籤：#Codex #ClaudeCode #Gemini #工作流 #開源工具 #高度討論Repo
- 熱度 / 討論理由（Repo）
  - Star / Fork：591★ / 108 forks（可視為近期有一定關注與擴散） citeturn4view0
  - 直接支援多家「CLI 代理」並用 MCP primitives（handoff/assign/send_message）做 supervisor–worker 協調，且每個 agent 以 tmux session 隔離運行（可控、可觀測、可中斷）。 citeturn2view1
- 重點摘要
  - CAO 的定位是「夾在你與各家 CLI agent 中間的本地 orchestrator」，以 supervisor 代理去啟動/派工多個 worker（真實 CLI 程式），支援平行/序列/群體協作。 citeturn2view1
  - 安裝路徑偏工程化（tmux + uv），但設計目標是不用重新包 API wrapper，就能沿用各 CLI 本身的 auth/工具能力。 citeturn2view1
- 對 Ewalk.ai 的白話幫助
  - 我們現在的「阿順」工作常常需要：一邊做資料整理/產檔、一邊做 repo 研究、一邊做規則回報。CAO 這類 orchestrator 的價值是：**把多 agent 真的拆成多個終端工作者**，讓「收集/摘要/驗證/產出」可以更像專案分工，並且每個 agent context 更乾淨（省 token、較不亂跑）。
- 建議狀態：可升級
  - 建議先做「小範圍試點」：只用在每日情報蒐集這類可回退任務（不碰對外發布/金流/廣告預算）。

### 3) COMPRESSION.md：用一個 repo 內的「壓縮規格檔」明確規定何時壓縮、保留什麼、丟掉什麼

- 來源標題：COMPRESSION.md — AI Agent Context Compression Protocol
- 來源連結：https://compression.md/
- 相關工具標籤：#省Token #自我升級 #工作流
- 重點摘要
  - 規格主張用 `COMPRESSION.md` 定義：觸發條件（例如 context 接近上限 75%）、策略（preserve_always / compress_aggressively）、目標壓縮比例（例如 0.50）。 citeturn2view5turn1search1
  - `preserve_always` 的概念是：某些核心資訊（system prompt、active task、最近幾輪、錯誤狀態、待辦）永遠不被摘要或丟棄，避免「壓縮後把規則壓掉」。 citeturn2view5

### 4) On the Effectiveness of Context Compression for Repository-Level Tasks（研究）：壓縮不只是省 token，可能「過濾噪音」反而提升 repo 任務表現

- 來源標題：On the Effectiveness of Context Compression for Repository-Level Tasks: An Empirical Investigation（arXiv:2604.13725）
- 來源連結：https://arxiv.org/abs/2604.13725
- 相關工具標籤：#省Token #自我升級 #工作流
- 重點摘要
  - 研究指出 repo-level 任務的長上下文會帶來：噪音遮蔽、截斷、延遲增加；而 context compression 可用來降低這些風險。 citeturn2view7
  - 在其測試中，壓縮不只是減少成本；某些方法在 4x 壓縮下甚至可能超過 full-context 的品質（作者解釋為過濾噪音）。 citeturn2view7
- 對 Ewalk.ai 的白話幫助
  - 這給我們一個判斷框架：**省 token 不是唯一目的**；更重要是把「噪音」丟掉、讓代理更容易抓到關鍵規則與關鍵素材。
- 建議狀態：先觀察
  - 先把它當「方法論證據」；要落地仍需我們對內部資料型態（Obsidian 筆記/腳本/模板）做一版適配策略。
