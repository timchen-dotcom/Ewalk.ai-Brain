- 來源連結：https://labs.cloudsecurityalliance.org/wp-content/uploads/2026/05/CSA_research_note_gemini_cli_rce_cvss10_ai_tool_security_20260502-csa-styled.pdf

- 重點摘要：
  - 報告指出 Gemini CLI 與其 GitHub Action 曾被列為最大嚴重度的 workspace trust 設計缺口：headless 模式自動信任工作目錄，且 `--yolo` 可能繞過 tool allowlist，導致 CI runner 在 sandbox 初始化前被注入任意命令。 citeturn3view0
  - 建議立即升級到 `@google/gemini-cli v0.39.1+`（或 preview track `v0.40.0-preview.3+`）與對應 Action 版本，並審計所有 headless CI 工作流是否會處理不受信任 PR/issue。 citeturn3view0
- 對 Ewalk.ai 的白話幫助：
  - 我們如果把任何「Agentic CLI」放進 CI/自動化（尤其對外 PR/外部輸入），一定要把 **信任邊界** 畫清楚：哪些 repo/資料是「不可信」，就不能給它跑會讀 secrets 的 agent。
  - 這是「自動化導入」的反面教材：不要因為省人力就把高權限密鑰交給會執行命令的 agent。
- 建議狀態：可升級（以「風險控管」角度：立刻盤點我們是否有把 Gemini CLI 類工具接進 CI；若未使用，則把這份報告納入我們的 Agent 安全檢核清單即可）。
