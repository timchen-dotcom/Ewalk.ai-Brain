## 可吸收重點

- **Claude Code Action v1.0**
  - v1.0 相對 beta/v0.x 有 breaking changes：升級前要先盤點 repo 內 workflow 依賴與事件觸發點，再改版本。
  - 升級落地應採「測試分支 → 最小回歸 → 可回退」的 SOP，而不是直接改主分支 workflow。
- **Token 省錢不是改 prompt 而已**
  - 先建立 run 的觀測（理想是 `token-usage.jsonl`；拿不到 token 就用代理指標：工具呼叫次數、讀檔量、耗時、輸出字數）。
  - 先砍結構性浪費：工具裁剪（tool pruning）、CLI 取代（CLI substitution）、預先抓資料（pre-fetch）。

## 系統優化判斷

- 高價值：
  - **把 Action 升級變成 SOP**：避免 CI/PR 工作流升級踩雷，且能被團隊複製。
  - **把 token 觀測與削減變成 SOP**：讓「省 token」可量化、可回歸、可持續改進。
- 暫不吸收：
  - 直接改動任何既有自動化腳本的行為（先讓 SOP 生效並累積 3 次以上觀測資料後，再決定要不要改腳本做自動記錄）。
