  - Profile 收斂是「權限隔離」的底座：把「只讀/可寫/可外送」切乾淨，降低自動化誤觸風險。  
  - MCP schema compact + 讀取工具並行，會直接縮短「讀資料」回合數與 token 成本，對我們這種多來源蒐集特別有感。

### 3) Tool-Schema Compression（TSCG）：工具定義本身就是「吃爆 context」的主因，壓縮後可恢復 RAG 可用性

- 來源標題：Tool-Schema Compression Enables Agentic RAG Under Constrained Context Budgets（arXiv:2605.26165）
- 來源連結：https://arxiv.org/abs/2605.26165
- 相關工具標籤：#省Token #自我升級 #工作流
- 重點摘要：
  - 論文指出：Agentic RAG 在「很多 tools」時會遇到致命衝突：tool schema 佔用 context，擠掉真正需要的檢索內容。  
  - 其保守壓縮設定可帶來約 44–50% 的 schema token 節省；在 8K context 下，原始 JSON schema 會溢出導致 EM 幾乎歸零，但壓縮後能明顯恢復正確率（文中報告平均 +20.5pp、外部驗證也有大幅提升）。  
- 對 Ewalk.ai 的白話幫助：
  - 我們的自動化很常「工具很多（Discord、Drive、GitHub、檔案系統…）」，但每次任務真正需要的工具可能只有 2–3 個；如果 tool schema 太肥，反而讓模型沒有空間讀素材。  
  - 這篇的結論可以直接變成我們的升級方向：把「工具 schema 壓縮 / 按需注入 / 對外工具與內部工具分層」當成省 token 的硬規格，而不是微調 prompt。  
- 建議狀態：可升級（先做「按需注入工具」與「工具 schema 瘦身」的小試點）

### 4) toon-format/toon：TOON（Token-Oriented Object Notation）— 用更省 token 的方式表達 JSON（高度討論 repo）

- 來源標題：Token-Oriented Object Notation (TOON) – Compact, human-readable, schema-aware JSON for LLM prompts. · GitHub
- 來源連結：https://github.com/toon-format/toon
- 相關工具標籤：#省Token #工作流 #高度討論Repo
-（若為 repo）熱度 / 討論理由：
  - GitHub 顯示 Star 約 24.4k、Fork 1.1k，屬於近期非常熱的「省 token / 結構化輸入」方向。  
  - Repo 本身提供 spec、benchmarks、TypeScript SDK，表示已往落地與可用性推進。  
- 重點摘要：
  - TOON 是「JSON 資料模型的另一種編碼」，目標是 token 更少、結構更清楚，並宣稱可作為既有 JSON 的 lossless 轉寫層（程式端仍用 JSON，給模型則用 TOON）。  
- 對 Ewalk.ai 的白話幫助：
  - 我們大量任務在傳遞「表格型資料」（貼文排程、素材清單、廣告組合、報表指標、待辦/交接單）。若能把 JSON 轉成更省 token 的格式，等於同樣 context 下能塞更多資料、或降低成本。  
- 建議狀態：先觀察（先做小規模試點：把 1 份「交接單/素材清單」從 JSON 改用 TOON 送入模型，比較 token 與錯誤率）
