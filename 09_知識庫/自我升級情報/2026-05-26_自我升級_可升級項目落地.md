## 可吸收重點

- 「常駐/長任務」需要可治理：能看狀態、能停、能恢復、能回退（Codex `remote-control` 的方向值得對照）。
- 「省成本」要先可拆帳：至少能拆到 skills/subagents/plugins/MCP server（Claude Code `/usage` 的拆法可參考）。
- 「多任務並行」預設要隔離工作區：worktree / 分支 / 獨立資料夾，避免上下文與未提交變更互相污染。
- 「規則/記憶」必須可追蹤：用變更單 + 審核（inbox/patch 思路）避免悄悄漂移。

## 系統優化判斷

- 高價值：
  - 先建立一份「Agent Harness 治理 checklist」，讓後續任何導入/升級都有一致的風險控管與驗收標準。
  - 把成本拆帳欄位寫進 checklist，避免只喊省 token 但無法定位來源。
- 暫不吸收：
  - 不把內容直接寫進 `AGENTS.md`、不改 `AI員工權限隔離規則`（避免未審核就變成全域規則）。
  - 不直接升級工具版本、不改任何自動化行為（升級需另外走回歸驗證與提姆先生批准）。
