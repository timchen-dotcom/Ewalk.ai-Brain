## 可吸收重點

- **Claude Platform on AWS**
  - Claude API 可透過 AWS endpoints 存取，並用 AWS IAM 與 AWS billing 走治理與帳務。
  - 可把「雲端常駐 agent」的落地阻力從「金鑰散落/帳務混亂」轉成「可控權限 + 可稽核帳務」的企業標準路徑。
- **Agent 記憶治理（Evidence-first + gated consolidation）**
  - 研究提醒：持續用 LLM 做 consolidated memory（不斷改寫整併）可能讓記憶變質，甚至表現下降。
  - 對我們的實務結論：**原始證據是第一級資料，摘要只能當索引**；整併要有 gate，不能每次互動都整併。

## 系統優化判斷

- 高價值：
  - **雲端 agent 治理盤點先行**：先把 IAM/帳務/工具/稽核的決策點整理好，後續要試點才不會臨時補洞。
  - **把「證據優先」變成入職/記憶規格**：避免 AI 員工用摘要覆蓋證據造成交付偏離（summary drift）。
- 暫不吸收：
  - 不直接導入任何新的雲端服務或改動既有自動化行為（先以盤點清單與規格落地）。
  - 不做「自動整併記憶」的程式化動作（先把規格與 gate 定義清楚，再決定是否工具化）。
