# 2026-05-14 自我升級 - 技能治理與工作流升級

## 來源

- Claude Code workflows（skills-only）：https://github.com/shinpr/claude-code-workflows
- Codex Skills Catalog（skill-installer）：https://github.com/openai/skills
- Agent-Skills Kit（skills 治理控制面）：https://github.com/jscraik/Agent-Skills

## 可吸收重點

- Claude Code：先導入 `dev-skills`（skills-only）當「規則守門員」，避免一次導入整套 orchestration；並注意不要與其他 workflows plugin 並裝，避免 skills 被靜默忽略。
- Codex：用 `$skill-installer` 安裝 curated/experimental skills；小步試點、安裝後重啟 Codex；任何外部連線設定（webhook/token）必須留在本地 `config.local.json`，不可進 repo。
- Skills 治理（Agent-Skills Kit 思路）：把「可提及的 skill」做成短 handle（指標），workflow 本體維持 canonical source；用投影（runtime projection）與 surface validation 做可驗證、可回滾治理，減少上下文負擔與 skill 漂移。

## 系統優化判斷

- 高價值：
  - **Claude Code skills-only 試點**：低干擾、容易回退，優先用在工程/腳本任務。
  - **Codex skills 導入策略**：以「可驗收的小 skill」起手（產檔/產草稿），逐步累積，避免技能庫膨脹失控。
  - **Agent-Skills Kit 的 handle/投影/檢查治理**：解決「技能越多越亂」與「每次載入成本太高」兩個核心痛點，且和 Ewalk.ai 長期 Vault 擴張方向一致。
- 暫不吸收：
  - 任何需要改動全域規則、或會影響對外輸出與權限邊界的自動化行為（先留在試點階段）。
