## 可吸收重點

### A) Codex 0.135.0（可治理/可診斷方向）

- `codex doctor` 變得更像「固定回歸檢查」：遇到卡住、thread/環境不一致更好定位。
- `/permissions` 能列出 named permission profiles：後續做「常駐自動化」可以用 profile 固定權限邊界（更可審核/可回退）。
- `/status` 顯示 remote transport/server version：常駐化可觀測性提升（知道到底連到哪、版本是什麼）。

### B) Claude Code v2.1.152（長任務穩定 + hooks 輸出治理）

- `SessionStart → reloadSkills`：讓 hook 安裝的 skills 在同 session 立即可用，降低重啟成本。
- `MessageDisplay` hook：可以在顯示層做「轉換/隱藏/折疊」，適合做輸出脫敏與縮短（降低 token、降低噪音）。
- `/usage` streaming read：大 session 檔案更不容易把記憶體打爆。

### C) CodeGraph（code knowledge graph / MCP）

- 把「找檔/找 flow」變成圖譜查詢，理論上可大幅降低 agent 在大型 repo 的反覆搜尋與重讀 token。
- `CODEGRAPH_MCP_TOOLS` 可限制暴露工具集合：利於權限隔離（只開必要工具）。

### D) RTK（CLI 輸出壓縮代理）

- 對高頻指令（`ls/tree/rg/git diff/test logs`）做「先壓縮再入模」：屬於低侵入、可回退的降本路線。
- 但它是 proxy，會介入輸入/輸出與上下文：需要更嚴格的風險控管與 PoC 驗收（避免敏感資料外漏、避免把關鍵資訊壓掉）。

## PoC（建議執行方式與驗收標準）

> PoC 原則：一律用「可回退、非敏感」的 repo；並用 [[../08_自動化/Agent Harness 治理 Checklist|Agent Harness 治理 Checklist]] 做權限與風險控管。

### 1) CodeGraph PoC（建議 60–90 分鐘）

- 目標：驗證「找 flow/trace」任務的 tool calls 與 token 是否下降、答案是否更穩。
- 任務腳本（建議用同一題目對照）：
  1. 問 agent：「這個 repo 的 X 流程從入口到輸出怎麼走？」（不指定檔案）
  2. 讓 agent 產出「可操作的修改建議」或「trace dossier」並指出關鍵檔案
- 驗收指標（至少 2 項達標）：
  - tool calls 減少（或總執行時間縮短）
  - 需要重問/重試的次數下降
  - 產出引用檔案更集中、路徑更準確
- 回退：PoC 只產生報告，不把工具寫進任何正式 SOP/自動化。

### 2) RTK PoC（建議 30–60 分鐘）

- 目標：驗證「高頻命令輸出」被壓縮後，仍能保留決策需要的關鍵訊號，同時降低 token。
- 任務腳本（建議固定 3 個命令類型）：
  - `rg`（大量結果）
  - `git diff`（大變更）
  - `test logs`（冗長輸出）
- 驗收指標（全部都要過）：
  - 關鍵錯誤訊息與檔案路徑不被壓掉
  - agent 仍能在一次回合內提出可用結論（不需要補問一堆）
  - token/費用觀感明顯下降（至少「可感知」）
- 風險控制（必做）：
  - 禁止任何含客戶敏感資料的 repo/檔案進 PoC
  - PoC 期間不允許對外發送/上傳/推送（只允許本地讀取）
