# Claude Code v2.1.128 升級重點與落地清單

用途：把 Claude Code 的版本更新「轉成可執行的習慣與檢查」，避免長任務/多分支協作踩坑。

來源（變更摘要）：https://newreleases.io/project/github/anthropics/claude-code/release/v2.1.128

---

## 可吸收重點（轉成我們的用法）

### 1) `.zip` 插件支援（`--plugin-dir`）

可落地的好處：

- 插件可以用「壓縮檔」當作可攜式版本封存（更容易版本鎖定、分享給同事、回退）。
- 建議未來內部把常用插件整理成「版本化的插件包」（例如 `plugins-YYYYMMDD.zip`），避免每台機器裝到不同版本。

### 2) Worktree 分支基準改為本地 `HEAD`

可落地的好處：

- 用 worktree 跑長任務時，較不容易因為「分支基準抓錯/未推的 commit」造成進度丟失。

落地規範（建議）：

- 長任務開始前先做一次「目前分支狀態確認」：  
  - 是否有未 commit 變更？  
  - 是否有未 push commit？  
- 要切 worktree 前，先明確決定「要不要先 push」再開始（避免多台機器/多人協作不同步）。

### 3) 子程序不再繼承 `OTEL_*`

可落地的好處：

- 降低「Claude Code 自己的 telemetry 設定」影響到被執行程式（尤其是本來就有 OTEL 的 app/腳本）。

---

## 建議升級與驗收方式（不改規則版）

1. 先在一台機器升級（或測試環境）跑 1～2 個低風險任務。  
2. 驗收清單（任一不過就先不要全員升級）：
   - worktree 任務能正常建立/切換/回收
   - 插件（若有）能用 `.zip` 安裝並正常載入
   - 跑 bash 工具時，既有專案的 OTEL 設定不會被意外改寫
