# 提姆先生與阿順工作模式

建立日期：2026-06-04
負責角色：阿順
最終決策者：提姆先生
狀態：OpenClaw First 工作模式規劃

## 核心結論

長期正式工作模式不是提姆先生每天直接用 Codex 跟阿順溝通。

正式模式應該是：

```text
提姆先生用筆電打開 OpenClaw 入口交辦
OpenClaw 在 Mac Studio 24H 接收、判斷、分派、追蹤
Codex 是 OpenClaw 底下的工程與文件專業員工
Command Center 是提姆先生的監控與批准中心
```

Codex 不是公司前台。Codex 是阿順底下的一位高能力工程員工。

## 筆電的定位

提姆先生的新筆電是「控制台」，不是阿順主機。

筆電負責：

- 跟阿順溝通
- 查看工作進度
- 審核批准事項
- 外出處理臨時急件
- 使用 Canva / 文件 / 瀏覽器做人工判斷
- 必要時遠端連回 Mac Studio

筆電不負責：

- 24H 長任務
- 大量自動化排程
- 正式 agent runtime
- 長時間素材處理
- 正式工具執行中樞

## Mac Studio 的定位

Mac Studio 是阿順主機。

Mac Studio 負責：

- OpenClaw 常駐運行
- 任務收件與分派
- AI 員工調度
- Codex 任務交辦
- Command Center 資料更新
- 客戶名冊 / 月報 / 週報 / 研究任務
- 低風險自動化
- 24H 工作紀錄與日報

## 提姆先生每天用什麼入口

### 第一入口：OpenClaw

用途：跟阿順說話、交辦工作、補資料、問進度。

這是長期正式入口。

提姆先生在筆電上使用 OpenClaw 入口，就像跟公司專業經理人阿順說：

```text
阿順，新增一個客戶
阿順，幫我整理這封信
阿順，這週幫 TheVision 做社群規劃
阿順，今天有哪些事情等我批准
阿順，幫我安排財務員工盤點訂閱
```

OpenClaw 收到後負責：

- 判斷任務類型
- 查 Ewalk.ai 系統資料
- 分派給 AI 員工或 Codex
- 建立任務紀錄
- 更新 Command Center
- 需要批准時送進 Approval Queue

### 第二入口：Command Center

用途：看狀態、看進度、看風險、做批准。

Command Center 不是聊天入口，而是老闆看公司營運的儀表板。

提姆先生在這裡看：

- 阿順主機是否正常
- 今天完成什麼
- 哪些任務卡住
- 哪些客戶缺資料
- 哪些內容待審
- 哪些高風險事項要批准
- AI 員工執行紀錄

### 第三入口：Codex

用途：臨時工程、文件、程式、修系統。

Codex 不是長期主要溝通入口，但仍保留。

適合直接用 Codex 的情境：

- 新筆電過渡期，Mac Studio 還沒重置前
- OpenClaw 還沒安裝完成前
- Command Center 壞掉，需要工程修復
- 需要精準修改檔案、SOP、程式碼
- 阿順要求提姆先生協助開啟某個本機專案

不適合用 Codex 的情境：

- 日常交辦
- 24H 自主運行
- 多員工分工調度
- 每天看工作進度
- 長期自動化流程入口

## 過渡期與正式期差異

### 過渡期：現在到 Mac Studio 重置完成前

目前 Mac Studio 還沒重置，所以不能開始正式 OpenClaw 主機施工。

過渡期做法：

```text
新筆電先安裝 Codex / Obsidian / Chrome
提姆先生先用 Codex 與阿順溝通
阿順協助搬移與驗收 Ewalk.ai 系統
Mac Studio 暫停正式主機施工
```

這時 Codex 是暫時入口，不是最終架構。

### 正式期：Mac Studio 重置並完成 OpenClaw 後

正式期做法：

```text
提姆先生用筆電打開 OpenClaw 入口
OpenClaw 24H 在 Mac Studio 運行
Command Center 顯示進度與批准事項
Codex 只在需要工程能力時被阿順調用
```

## 每天實際工作流

### 早上

提姆先生打開筆電：

1. 看 Command Center
2. 看「今天需要你批准」
3. 看「阿順昨晚完成什麼」
4. 用 OpenClaw 跟阿順補充交辦

### 白天

提姆先生只要丟任務給 OpenClaw：

```text
阿順，幫我把這個客戶建進名冊
阿順，幫我安排這週社群內容
阿順，這個素材幫我分類
阿順，幫我查這個工具適不適合導入
```

OpenClaw 自動分派：

- 資料整理員
- 社群主編
- 廣告企劃
- GitHub 研究員
- 財務稽核員
- Codex 工程員

### 晚上

阿順產生日報：

- 今天完成什麼
- 哪些任務還在跑
- 哪些等提姆先生批准
- 哪些客戶缺資料
- 明天自動接續什麼

## 權限原則

OpenClaw 可以自動做：

- 讀資料
- 整理資料
- 建草稿
- 建任務
- 更新內部文件
- 更新 Command Center 本機狀態
- 產出報告草稿
- 分派 AI 員工

OpenClaw 必須送審：

- 發文
- 寄正式信
- 調廣告預算
- 取消或變更訂閱
- 改付款方式
- 正式部署網站
- 開啟付費雲端資源
- 新增高權限 token
- 修改核心規則

## 筆電上建議放的入口

| 入口 | 用途 | 優先級 |
| --- | --- | --- |
| OpenClaw Web / Chat UI | 跟阿順日常溝通與交辦 | 第一優先 |
| Command Center | 看進度、審核、批准 | 第一優先 |
| Chrome Remote Desktop / Tailscale / 螢幕共享 | 必要時連回 Mac Studio | 第二優先 |
| Codex Desktop | 工程急件與過渡期使用 | 第三優先 |
| Obsidian | 外出閱讀與補資料 | 第三優先 |

## 阿順判斷

提姆先生每天最理想的使用方式是：

```text
90%：OpenClaw 跟阿順溝通
8%：Command Center 看進度與批准
2%：Codex / Obsidian 處理臨時技術或文件急件
```

所以答案是：

```text
正式入口應該是 OpenClaw，不是 Codex。
Codex 是阿順底下的專業員工。
Command Center 是提姆先生看公司運作的儀表板。
```
