# 2026-06-07 B29 OpenClaw 高權限總閘門

## 一句話結論

B29 一次開啟發文、部署、production Firebase 改狀態、正式客戶通道、廣告預算與金流六類高權限能力，但開啟方式是 `enabled_with_explicit_approval`；沒有提姆先生針對單一 action 的明確批准時，只能 preview / draft / approval item。

## 從 blocked 改成 approval_required 的能力

```text
發文 / 排程發文
部署
production Firebase 改狀態
正式客戶通道
廣告預算
金流 / 帳務 / 付款設定
```

## 不再做的事

- 不再把上述六類視為永久禁止。
- 不再因為牽涉外部副作用就停在純文字整理。
- 不再把 OpenClaw 限制在陪聊狀態。

## 仍然需要的批准

每一個高權限 action 執行前必須具備：

- `approval_id`
- `capability_id`
- `client_or_project`
- `requested_action`
- `risk_summary`
- `preview_or_diff_path`
- `rollback_or_recovery_plan`
- `approved_by`
- `approval_text`
- `approved_at`

## B29 通過後代表什麼

代表：

- OpenClaw 可以準備發文、部署、Firebase 寫入、正式通道、廣告與金流相關工作。
- OpenClaw 可以產生 preview、diff、審稿清單、approval item、action queue。
- Codex / Command Center 可以在提姆先生批准後進入執行流程。

不代表：

- OpenClaw 可以無批准直接發文。
- OpenClaw 可以無批准直接部署。
- OpenClaw 可以無批准修改 production Firebase。
- OpenClaw 可以無批准接正式客戶通道。
- OpenClaw 可以無批准啟用廣告、提高預算、付款或改付款方式。

## 上工判定

B26-B29 全部通過後停止擴驗證，OpenClaw 進入高權限受控上工模式。

優先處理積壓工作：

1. 嘉昱隔熱膜：廣告素材、LINE 承接、上線前 approval item。
2. 韓食日常鍋物：貼文 preview、發文 approval item。
3. Command Center：把待批准 action queue 轉成可決策清單。
4. 每日交接：整理三天重建成果與明日作業。
