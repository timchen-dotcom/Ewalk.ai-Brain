# 網站發佈標準路徑與免重複核准方案

## 用途

統一 Ewalk.ai 的網站、Demo、客戶原型與內部工具發佈方式，降低每次上架都要重新確認路徑、重新批准 Vercel CLI、重新整理檔案位置的摩擦。

## 目前問題

目前網站檔案分散在多個位置：

- Vault 根目錄：已有 `.vercel`，目前綁定 `lin-teacher-garage`。
- `Ewalk.ai Brain/01_客戶/.../03_提案與交付/...`：客戶提案 Demo。
- `Ewalk.ai Brain/01_客戶/.../02_網站與系統/...`：客戶網站或系統原型。
- `Ewalk.ai Brain/08_自動化/...`：公司內部工具與自動化 MVP。
- `tmp/open-design/...`：臨時產出的設計或部署備份。

這會造成幾個問題：

1. 同一個工作區同時混有 Obsidian Vault、網站原始碼、部署輸出與臨時檔案。
2. 根目錄的 `.vercel` 已綁定特定專案，容易誤把其他工具部署到錯誤專案。
3. 每次從深層中文路徑部署，都會形成新的 CLI 命令與新的批准情境。
4. 網站沒有固定「準備上線區」，阿順每次都要重新判斷要從哪個資料夾發佈。
5. 沒有 GitHub / Vercel 自動部署鏈路時，每次上線都依賴本機 CLI。

## 判斷

現在的問題不是 Vercel 本身，而是「發佈路徑」和「專案邊界」不夠乾淨。

Obsidian Vault 適合存放策略、SOP、客戶資料、Prompt、交接單與原型說明；但正式要發佈到網路的網站，應該進入固定的網站工作區，再由 GitHub 或 Vercel 專案自動部署。

## 建議標準路徑

在工作區根目錄建立固定資料夾：

```text
sites/
  ewalk-tools/
    google-review-helper/
  client-demos/
    kgc-ai-compliance-demo/
    theday-order-test/
  client-sites/
    lin-teacher-garage/
```

規則：

- `Ewalk.ai Brain`：保留為知識庫與交付文件。
- `sites/ewalk-tools`：公司可複用工具。
- `sites/client-demos`：提案、展示、短期 Demo。
- `sites/client-sites`：較正式、可能掛網域或長期維護的客戶網站。
- `tmp`：只放臨時產物，不直接部署。

## 免重複核准方向

### 第一階段：固定本機部署入口

建立固定部署腳本：

```text
deploy-site-preview.command
deploy-site.command
```

只允許從 `sites/` 底下選擇專案部署。之後低風險 Preview 只需要批准 `deploy-site-preview.command` 這個固定入口，不需要每次批准不同深層路徑的 Vercel 指令。

### 第二階段：GitHub + Vercel 自動部署

把 `sites/` 內的正式專案放入 GitHub repo，Vercel 綁定 GitHub：

- push 到分支，自動產生 Preview URL。
- merge 到 main，自動部署正式站。
- 阿順只需要更新檔案、提交、推送，不需要每次手動跑 `vercel deploy`。

### 第三階段：建立發佈佇列

所有待上線項目先進文件：

```text
Ewalk.ai Brain/08_自動化/網站發佈佇列.md
```

欄位包含：

- 專案名稱
- 網站類型：內部工具 / 客戶 Demo / 正式網站
- 原始資料位置
- 發佈工作區位置
- Vercel 專案
- Preview URL
- Production URL
- 風險等級
- 是否需要提姆先生批准

## 發佈權限規則

可以低摩擦自動發佈：

- 內部工具 Preview
- 客戶提案 Demo Preview
- 未掛正式網域的測試站
- 無個資、無金流、無廣告承諾、無醫療或財務高風險聲明的靜態頁

仍需提姆先生批准：

- 正式客戶官網上線
- 綁定正式網域
- 對外公開價格、優惠、車況、醫療、保健、財務、法律相關內容
- 涉及金流、登入、客戶資料或第三方 API token
- 覆蓋既有正式網站

結論：要達成低摩擦快速發佈，下一步不是重複登入 Vercel，而是建立長期 `VERCEL_TOKEN` 或改接 GitHub + Vercel 自動部署。

## 固定部署入口

```bash
./deploy-site-preview.command ewalk-tools/google-review-helper
```

此入口會：

- 只允許部署 `sites/` 底下的專案。
- 使用固定的本機 Vercel CLI：`.tools/bin/vercel`。
- 使用固定的 Vercel HOME：`.vercel-home`。
- 部署後自動寫入 `網站發佈紀錄`。
- 只做 Preview，不會覆蓋正式 Production。
