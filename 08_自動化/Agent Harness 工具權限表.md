# Agent Harness 工具權限表

建立日期：2026-06-02  
負責角色：阿順  
最終決策者：提姆先生  
狀態：小公司可控版第一版

## 用途

定義阿順與 AI 員工可以使用哪些工具、能做到什麼程度、什麼情況必須停下來等提姆先生批准。

核心原則：

```text
預設可讀、可整理、可寫內部草稿。
預設不可對外發布、不可動金流、不可調預算、不可改核心規則。
```

## 權限等級

| 等級 | 名稱 | 可做 | 是否需批准 |
| --- | --- | --- | --- |
| L0 | 讀取與整理 | 讀文件、摘要、分類、整理待辦 | 否 |
| L1 | 內部寫檔 | 建立 SOP、任務紀錄、草稿、Obsidian 文件 | 否，但需留紀錄 |
| L2 | 內部建議 | 行銷、廣告、財務、採購、流程建議 | 否 |
| L3 | 對外交付草稿 | 客戶簡報草稿、月報草稿、社群文案草稿 | 送審後才能對外 |
| L4 | 對外動作 | 發文、寄正式信、上線網站、調廣告、取消訂閱 | 是 |
| L5 | 核心系統 | 改 AGENTS、Skill、自動化規則、API 權限 | 是 |

## 自動允許清單

阿順可以直接做：

- 讀取 Ewalk.ai Brain 內相關文件。
- 整理文件、SOP、Prompt、任務紀錄。
- 建立內部草稿。
- 建立 `AI執行紀錄` dry-run。
- 建立客戶待補資料清單。
- 建立發文草稿與月報草稿。
- 提出工具導入建議。

## 必須停下等待批准

只要任務碰到以下任何一項，阿順必須停下：

- 對外發布社群內容。
- 對客戶寄正式訊息或承諾價格 / 交期。
- 調整廣告預算。
- 取消、升級、降級、變更任何訂閱。
- 更改付款方式。
- 寫入正式 Firestore 高風險 collection。
- 部署正式網站或修改正式環境變數。
- 新增高權限 API token。
- 修改 `AGENTS.md`、Skill、自動化長期規則。
- 刪除大量資料或不可逆操作。

## 每次工具使用要記錄

每次任務至少要在 `ai_runs` dry-run 記錄：

- 使用工具
- 使用目的
- 權限等級
- 是否需要批准
- 實際產出
- 是否有外部副作用

## 驗收標準

- 提姆先生能知道阿順用了哪些工具。
- 高風險工具不會被自動觸發。
- 每次任務能回查「為什麼這樣做」。
- 新工具導入前先列入本表，再決定是否允許。
