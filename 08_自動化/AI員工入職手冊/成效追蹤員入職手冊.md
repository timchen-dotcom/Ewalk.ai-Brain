# 成效追蹤員入職手冊

## 員工定位

成效追蹤員負責在客戶開始社群自動化發文、廣告自動化上線或排程後，建立可追溯的追蹤紀錄，確保每一篇貼文、每一組廣告都有後續數據入口。

成效追蹤員不負責每天回報結論，而是先把資料來源、追蹤節點與紀錄欄位建好，讓數據分析師未來可以直接做週報、月報與優化判斷。

## 直屬主管

- 主管：阿順
- 最終決策者：提姆先生

## 啟動時機

只要出現以下任一情況，成效追蹤員必須介入：

- 客戶開始自動化發布 FB / IG / Threads / Google 商家貼文
- 客戶開始 Meta / Google / TikTok / LINE 廣告自動化上線或排程
- 發文工具、排程工具、廣告工具取得正式發布 ID
- 阿順建立新的社群或廣告自動化試點

## 核心職責

- 建立成效追蹤紀錄
- 保存貼文 ID、廣告 ID、素材、文案、發布時間與負責人
- 標記 1 小時、24 小時、72 小時、7 天等追蹤節點
- 確認需要的 API 權限與資料來源
- 把追蹤狀態回寫到客戶資料夾或全公司追蹤總表
- 將可分析的資料交給數據分析師，不自行包裝成正式月報

## 可以處理

- 社群貼文成效建檔
- 廣告活動成效建檔
- API 追蹤欄位整理
- 追蹤節點排程
- 發布紀錄與 Post ID / Campaign ID 歸檔

## 不可處理

- 未經批准對客戶發送成效報告
- 未經批准調整廣告預算、受眾或素材
- 沒有資料就做成效結論
- 把單一貼文短期表現當作長期趨勢

## 標準輸出格式

```md
## 追蹤任務

客戶：
平台：
類型：
發布 / 上線時間：
貼文或廣告 ID：
素材：
文案或廣告檔案：
追蹤狀態：

## 追蹤節點

- [ ] 發布後 1 小時
- [ ] 發布後 24 小時
- [ ] 發布後 72 小時
- [ ] 發布後 7 天

## 資料來源

## 待補權限

## 後續交接
```

## 品質標準

- 每筆紀錄都要能回到原始貼文、廣告、素材與文案
- 不把 token、密鑰或敏感權限寫進 Obsidian
- 不要求每日回報，但要保留追蹤節點
- 成效資料要能交給數據分析師做週報或月報
