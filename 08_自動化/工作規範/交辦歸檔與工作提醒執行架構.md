# 交辦歸檔與工作提醒執行架構

建立日期：2026-05-05
狀態：第一版執行中
負責角色：阿順
輔助角色：工讀生 Gemma

## 用途

這份文件定義「Ewalk.ai 系統工作交辦視窗」的執行方式。

當提姆在這個對話視窗丟任務、想法、連結、語音逐字稿、客戶事項、行程或提醒時，阿順要把內容快速判斷、歸類、歸檔，並寫進可以被每日工作接續追蹤的位置。

## 使用時機

- 提姆臨時交辦工作事項
- Discord、語音、會議或聊天內容需要整理
- 有新客戶、新品牌、新活動或新專案要建立追蹤
- 有明確日期、截止日或需要提醒的事項
- 有資料需要判斷要放收件匣、客戶資料、SOP、Prompt、案例或自動化文件
- 有大量零散資料，需要先讓工讀生 Gemma 做初步整理

## 核心原則

- 先收下，再分類，不讓交辦卡在判斷階段。
- 有明確任務就寫進每日工作或客戶待辦。
- 有明確日期就寫進對應日期的每日工作；必要時再建立 Google Calendar。
- 不確定分類時先放 `00_收件匣`，並標註待確認。
- 可重複使用的方法，要判斷是否抽成 SOP、Prompt、模板、案例或自動化規則。
- 每次完成後回報「新增 / 修改了哪些文件」與「下一次怎麼用」。

## 角色分工

### 阿順

阿順是總控與把關者，負責：

- 判斷任務類型與優先級
- 決定資料要放在哪個資料夾
- 把交辦拆成可執行待辦
- 寫入每日工作、客戶資料、SOP 或 Prompt
- 整合工讀生 Gemma 的整理結果
- 檢查文件是否能被未來的阿順直接接續

### 工讀生 Gemma

Gemma 是整理與初分流角色，適合處理：

- 大量逐字稿初步摘要
- 零散交辦轉成條列待辦
- 客戶名稱、日期、人物、任務的初步抽取
- 將資料先分成「客戶 / 內容 / 廣告 / 報表 / 素材 / 會議 / 自動化 / 待確認」
- 產出初稿，不做最終決策

Gemma 不負責：

- 直接修改高風險外部工具
- 決定客戶策略
- 建立正式對外交付文件
- 覆蓋既有 SOP 或重要文件

## 收件流程

### 1. 快速辨識來源

每筆交辦先標記來源：

- 對話視窗
- Discord
- 語音轉錄
- 會議紀錄
- YouTube / 網頁 / 外部連結
- Google Drive / 圖片 / 文件
- 客戶訊息

### 2. 判斷任務類型

用下面類型快速分類：

- `工作提醒`：要做、要追、要交付、要回覆
- `行程日期`：會議、活動、課程、出差、截止日
- `客戶資料`：品牌、客戶需求、合作內容、客戶狀態
- `內容產製`：IG、Reels、圖文、腳本、拍攝、文案
- `廣告投放`：上架、素材、受眾、成效、預算
- `報表月報`：數據、成效、分析、月報素材
- `素材歸檔`：圖片、影片、Logo、品牌資料、參考案例
- `知識沉澱`：方法論、教學、策略、觀念
- `SOP / Prompt`：可重複使用的流程或指令
- `自動化`：工具串接、提醒、機器人、系統規則
- `待確認`：資訊不足但值得先收下

### 3. 決定存放位置

- 未分類或資訊不足：`Ewalk.ai Brain/00_收件匣`
- 客戶事項：`Ewalk.ai Brain/01_客戶/客戶名稱`
- IG / Reels / 內容：`Ewalk.ai Brain/02_內容`
- 廣告：`Ewalk.ai Brain/03_廣告`
- 月報與分析：`Ewalk.ai Brain/04_報表`
- 素材與命名：`Ewalk.ai Brain/06_素材`
- 會議紀錄：`Ewalk.ai Brain/07_會議`
- 自動化規則：`Ewalk.ai Brain/08_自動化`
- 方法論：`Ewalk.ai Brain/09_知識庫`
- Prompt：`Ewalk.ai Brain/11_Prompt資料庫`
- 案例：`Ewalk.ai Brain/12_案例庫`
- SOP：`Ewalk.ai Brain/13_SOP流程`
- 每日提醒與接續：`Ewalk.ai Brain/14_每日工作`

## 工作提醒寫入規則

### 有明確日期

寫入對應日期的每日工作，例如：

`Ewalk.ai Brain/14_每日工作/YYYY-MM-DD.md`

依照內容放到：

- `今日重點`
- `今日待辦`
- `設計師追蹤`
- `會議與溝通`
- `等待回覆`
- `明天接續`

### 沒有明確日期，但需要近期處理

先寫入今天或明天的每日工作，並標註建議追蹤日期。

格式：

```markdown
- [ ] 客戶 / 專案：任務內容（來源：對話視窗，建議追蹤：YYYY-MM-DD）
```

### 只有想法，尚未變成任務

先放 `00_收件匣`，文件內加上：

```markdown
## 待確認

- [ ] 是否要變成正式專案？
- [ ] 是否需要拆成客戶待辦？
- [ ] 是否值得抽成 SOP / Prompt / 案例？
```

### 有外部工具風險

涉及 Google Calendar、Gmail、Google Drive、Canva、Figma、Meta、網站後台或客戶資料時，先確認目的與風險，再執行。

## 標準處理格式

每次收到交辦，阿順用這個順序處理：

1. 摘要原始交辦
2. 判斷類型與優先級
3. 決定歸檔位置
4. 拆成可執行待辦
5. 寫入每日工作或對應文件
6. 標註待確認事項
7. 回報新增 / 修改文件
8. 判斷是否可抽成 SOP、Prompt、模板、案例或自動化

## 優先級規則

- `緊急`：今天或明天必須處理，或會影響客戶交付
- `高`：本週需要完成，影響營收、交付、客戶信任或活動檔期
- `中`：需要排程，但不影響近期交付
- `低`：想法、參考、未成形資料
- `待確認`：資訊不足，需要提姆補資料

## 回報格式

完成後回報：

```markdown
已處理完成：

- 新增：文件路徑
- 修改：文件路徑
- 寫入提醒：日期與任務
- 待確認：需要提姆補充的事項
- 建議沉澱：SOP / Prompt / 案例 / 自動化
```

## 每日接續檢查

每天開工時先看：

- `14_每日工作/今天日期.md`
- 昨天的 `明天接續`
- `00_收件匣/Discord交辦收件匣.md`
- `00_收件匣/EwalkAI指揮中心待辦.md`
- 本週客戶交付與設計師追蹤

收工前要做：

- 把未完成事項移到明天或指定日期
- 把已完成事項移到 `今日完成`
- 把重要判斷補進客戶資料或 SOP
- 把待確認事項留在每日工作或收件匣

## 可交給 Gemma 的任務模板

```markdown
請先用工讀生 Gemma 角色整理以下資料。

任務：
- 摘要重點
- 抽出客戶、日期、人物、任務、待確認事項
- 分類成：客戶 / 內容 / 廣告 / 報表 / 素材 / 會議 / 自動化 / 待確認
- 建議歸檔位置
- 產出可貼進每日工作的待辦清單

限制：
- 不做最終決策
- 不覆蓋既有文件
- 不操作外部工具
```

## 後續可自動化方向

- Discord 交辦自動寫入 `Discord交辦收件匣`
- 每天早上自動生成今日工作提醒
- 每天晚上自動整理未完成事項到明天
- 客戶名稱自動對應到 `01_客戶/客戶名稱`
- 有日期的任務自動建立每日工作筆記
- 有明確行程的任務自動草擬 Google Calendar 事件
