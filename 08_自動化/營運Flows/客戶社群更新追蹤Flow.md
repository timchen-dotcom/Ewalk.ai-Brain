# 客戶社群更新追蹤 Flow

建立日期：2026-06-02
狀態：MVP 已建立
主管：阿順
最終決策者：提姆先生

## 觸發條件

- 每週固定巡檢客戶 IG / FB 發文數
- 客戶月報前需要整理內容更新穩定度
- 客戶抱怨社群沒有持續更新
- 社群主編需要知道本週還差幾篇
- 自動發文系統發布後需要確認是否有達標

## 輸入

- 客戶追蹤設定
- IG / FB 發文資料
- 每週目標篇數
- 每月目標篇數
- 報告日期

## 流程

1. 成效追蹤員讀取客戶設定檔。
2. 系統依資料來源取得貼文資料。
3. 系統計算本週與本月發文數。
4. 系統比對目標篇數並產出缺口。
5. 阿順依狀態分派：
   - 正常：歸檔即可。
   - 稍微落後：交社群主編補排。
   - 嚴重落後：交客戶成功經理追素材或授權。
   - 待授權：補 Meta 權限。
6. 月底交數據分析師併入月報。

## 輸出

- Markdown 週 / 月追蹤報告
- CSV 明細
- 需要提醒清單
- 月報素材

## 升級路線

### 第 1 階段：dry-run 與手動資料

- 用範例資料驗證計算規則。
- 用手動 JSON / CSV 補貼文資料。
- 每週由阿順或成效追蹤員執行。

### 第 2 階段：Meta API 讀取

- Facebook Page 使用 Page token 讀取貼文。
- Instagram 使用 Instagram Business 帳號讀取媒體。
- API 只讀，不發文。

### 第 3 階段：定時排程

- 每週一或每週五自動執行。
- 報告自動放進 `04_報表/社群更新追蹤`。
- 缺口項目進 Discord 通知草稿。

### 第 4 階段：Command Center

- 將追蹤結果寫入 Firebase。
- Command Center 顯示客戶本週更新燈號。
- 嚴重落後自動進待辦。

## 風險控管

- 讀取 API 權限與發布 API 權限分離。
- 客戶授權不足時，先標記待授權，不硬抓資料。
- 對外提醒前需提姆先生批准。
- 週 / 月目標若涉及合約承諾，需回到正式合約確認。
