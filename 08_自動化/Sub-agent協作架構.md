# Ewalk.ai Sub-agent 協作架構

建立日期：2026-05-15
狀態：規劃中

## 架構判斷

Ewalk.ai 可以先直接建立自己的 Sub-agent 架構，不需要等外部工具全部成熟才開始。

但架構設計要參考 GitHub 上成熟專案的共同做法：

- Sub-agent 要像專門員工，不是另一個會亂跑的阿順。
- 每個 Sub-agent 要有明確職責、可讀資料、可用工具、不可做的事與回報格式。
- Sub-agent 的價值在於節省主對話上下文、分工並行、專業化檢查。
- 不要一次建立太多角色，先從最常用、最能省時間、最容易驗收的角色開始。
- 能重複的工作沉澱成 Skill；會固定交付的角色沉澱成入職手冊。

外部參考方向：

- Gemini CLI Subagents：Sub-agent 是主 Agent 可委派的專家，擁有獨立上下文與工具範圍。
- Claude Code Subagents 類專案：常見做法是每個 agent 都有清楚描述、使用時機、品質檢查與輸出格式。
- Arc / Agent Skills 類專案：成熟架構會把 Agent、Sub-agent、Skills、Tools 分層，不把所有能力塞進同一份提示詞。

## 核心觀念

阿順不是要自己完成所有任務，而是要成為 Ewalk.ai AI Command Center 的總控大腦。

成熟工作流應該是：

```text
Agent：阿順，統籌任務與主對話
Sub-agent：專門分工與摘要回報
Skills：封裝可重複使用的流程
Tools：連接外部服務與資料
```

重點不是讓 AI 自動亂跑，而是：

- 把任務拆清楚
- 把權限設清楚
- 把上下文管清楚
- 把回報格式固定

## 什麼時候適合用 Sub-agent

- 任務可以拆成獨立子任務
- 子任務彼此不會互相覆蓋檔案
- 需要不同專業知識
- 希望主對話只保留摘要，不被細節塞滿
- 可以並行進行研究、整理、檢查或草稿產出
- 子任務有明確輸入、輸出、完成標準

範例：

- 一位 Sub-agent 查 GitHub 自我升級 repo
- 一位 Sub-agent 整理台灣美感趨勢
- 一位 Sub-agent 檢查簡報美感
- 一位 Sub-agent 整理客戶資料
- 一位 Sub-agent 做月報數據初稿

## 什麼時候不適合用 Sub-agent

- 一步就能完成的小任務
- 高風險、不可逆操作
- 需要提姆先生親自判斷的決策
- 涉及金流、合約、帳密、客戶正式承諾
- 任務範圍不清楚，容易越做越歪
- 子任務會互相修改同一份重要文件

## 第一批優先建立角色

Ewalk.ai 目前已升級為 AI 行銷整合公司架構，因此第一批角色以客戶交付為優先。

| 優先 | 角色 | 為什麼先做 |
| --- | --- | --- |
| 1 | 專案助理 | 每個客戶都需要拆任務、排時程、追進度 |
| 2 | 客戶成功經理 | 新客戶進來時需要先釐清需求與合作範圍 |
| 3 | 社群主編 | TheVision 這類客戶最需要穩定 IG / FB 更新 |
| 4 | 廣告投放專員 | 檔期活動與 Meta 廣告需要獨立檢查流程 |
| 5 | 成效追蹤員 | 只要開始自動化發社群或廣告，就要先建檔與追蹤 |
| 6 | 數據分析師 | 每週與每月要能回報成效，不只產內容 |
| 7 | 設計企劃 | 內容、活動、廣告都需要視覺需求整理 |
| 8 | 訂閱稽核員 | 控制公司工具成本，避免不必要訂閱 |

並行保留的自我升級角色：

- GitHub 研究員
- 美感趨勢研究員
- 簡報美感檢查員

## Sub-agent 成熟度分級

### L1：臨時分工

使用時機：

- 單次任務
- 不需要長期記憶
- 只需要回報摘要

範例：

- 幫某份簡報找 5 個競品案例
- 幫某次會議整理待辦

### L2：固定角色

使用時機：

- 任務會重複出現
- 需要固定輸出格式
- 需要入職手冊

範例：

- GitHub 研究員
- 美感趨勢研究員
- 簡報美感檢查員

### L3：半自動流程

使用時機：

- 有固定排程
- 會讀取外部資料
- 會寫入指定資料庫
- 需要提姆先生批准後才能改系統

範例：

- 每日 GitHub 自我升級情報
- 每日美感趨勢文章收集
- 每週五美感趨勢週報

### L4：可營運 AI 部門

使用時機：

- 多個 Sub-agent 可以互相接力
- 阿順只負責分派、整合、把關與向提姆先生回報
- 所有角色都有入職手冊、SOP、權限規則與驗收標準

這是 Ewalk.ai 長期目標，不是第一階段要一次完成。

## 分派格式

阿順分派 Sub-agent 時，要給清楚格式：

```md
## 任務

## 背景

## 可讀資料

## 不可做的事

## 輸出格式

## 完成標準
```

## 回報格式

Sub-agent 回報時，只給阿順可整合的摘要：

```md
## 結論

## 重要發現

## 建議行動

## 風險 / 待確認

## 來源或修改檔案
```

## 權限原則

- Sub-agent 只做分工，不做最終決策。
- 涉及全域規則、客戶承諾、金流、合約、API key、自動化行為，要回到阿順與提姆先生確認。
- 每位長期 Sub-agent 都要有入職手冊。
- 可重複流程要沉澱成 Skill 或 SOP，不要每次重教。
- Sub-agent 不直接覆寫核心規則，包含 `AGENTS.md`、Skill、SOP、客戶正式交付文件。
- Sub-agent 若提出自我升級建議，必須先形成提案，由阿順整理給提姆先生批准。

## 驗收標準

一位 Sub-agent 可以正式進入 Ewalk.ai Command Center 前，至少要符合：

- 有角色定位
- 有主管與回報對象
- 有可做 / 不可做清單
- 有可讀取資料範圍
- 有輸出格式
- 有品質標準
- 有風險與升級回報規則
- 有 1 個可測試任務

## 建立流程

1. 確認這個角色是否真的需要長期存在。
2. 先用一次性任務測試它是否有價值。
3. 若重複出現 3 次以上，建立入職手冊。
4. 若流程穩定，沉澱成 SOP 或 Skill。
5. 若需要排程，納入自動化。
6. 若會影響客戶交付或系統規則，必須由提姆先生批准。

## 對 Ewalk.ai 的價值

Sub-agent 最適合幫 Ewalk.ai 解決三件事：

1. 降低阿順主對話的上下文負擔。
2. 讓不同專業任務可以並行。
3. 把 AI 員工制度化，從單一助理變成可管理的 AI 團隊。
