# AI 部門任務分類、佇列與回報規則

建立日期：2026-05-15
主管：阿順
最終決策者：提姆先生

## 目的

讓提姆先生只需要用自然語言交辦，阿順就能判斷任務類型、啟動對應部門、安排工作節奏，最後用統一格式回報。

## 任務分類

| 任務類型 | 啟動部門 | 是否可自動做 | 需要批准的地方 |
| --- | --- | --- | --- |
| 新客戶啟動 | 客戶成功與策略部、專案管理部 | 可建立資料夾與盤點文件 | 合作範圍、交付承諾 |
| 社群經營 | 社群內容部、視覺設計部、成效追蹤員、數據報表部 | 可產出內容草稿與月曆 | 對外發布、更新頻率承諾 |
| 檔期活動 | 客戶成功與策略部、社群內容部、廣告投放部 | 可產出活動草案 | 活動主軸、優惠、預算 |
| 廣告投放 | 廣告投放部、成效追蹤員、數據報表部 | 可產出 Brief 與檢查表 | 實際上線、預算、帳戶設定 |
| 月報 | 數據報表部、客戶成功與策略部 | 可產出初稿 | 對客戶正式交付 |
| 素材整理 | 視覺設計部、專案管理部 | 可整理素材清單與需求 | 對外交付成品 |
| 自我升級 | AI 自動化與知識管理部 | 可收集與提出提案 | 修改系統核心規則 |
| 財務訂閱 | 財務與訂閱稽核部 | 可整理費用與建議 | 取消、降級、改付款 |

## 自動化成效追蹤規則

只要客戶開始自動化發社群或自動化投放廣告，阿順必須分派成效追蹤員建檔。

建檔優先於分析。第一階段不需要每日回報，但必須留下：

- 客戶、平台、貼文或廣告類型
- 發布時間或上線時間
- Post ID、Photo ID、Campaign ID、Ad Set ID 或 Ad ID
- 文案與素材來源
- 追蹤節點：1 小時、24 小時、72 小時、7 天
- 資料來源與待補 API 權限
- 後續交接給數據分析師的狀態

## 任務佇列

每個任務進入後，阿順要放入其中一種佇列：

### A. 立即處理

條件：

- 影響今天交付
- 客戶正在等待
- 提姆先生明確要求現在做

### B. 本週處理

條件：

- 需要分工
- 有明確交付時間
- 與本週內容、廣告、月報相關

### C. 排程處理

條件：

- 每日、每週、每月重複
- 需要自動化或提醒
- 需要固定資料來源

### D. 待補資料

條件：

- 缺少帳號、素材、預算、客戶窗口、社群連結
- 需要提姆先生或客戶補資料

### E. 待批准

條件：

- 涉及對外承諾
- 涉及金流
- 涉及廣告預算
- 涉及取消訂閱
- 涉及系統核心規則

## 阿順分派格式

```md
## 任務名稱

## 任務類型

## 啟動部門

## 背景

## 可用資料

## 本次要產出

## 不可做的事

## 完成標準

## 回報期限
```

## 部門回報格式

```md
## 結論

## 已完成

## 重要發現

## 建議下一步

## 風險 / 待確認

## 來源或修改檔案
```

## 阿順回報提姆先生格式

```md
## 我已經安排

## 目前產出

## 缺少資料

## 需要您批准

## 下一步我會做
```

## Token 使用決策

可以多花 Token：

- 會影響客戶交付品質
- 需要策略判斷
- 需要跨部門整合
- 需要產出正式文件、提案、月報

要節省 Token：

- 單純分類
- 固定格式整理
- 已有 SOP 可照做
- 只需要摘要回報

## 驗收標準

- 任務能被分類
- 任務能被排進佇列
- 任務知道啟動哪些部門
- 任務知道哪些可以自動做、哪些要批准
- 回報格式一致
