# 美業多分店內部訂購系統 MVP 需求規格

建立日期：2026-05-24
狀態：MVP 規格草案
需求來源：提姆先生
負責整合：阿順

## 1) 任務一句話

開發一套網站入口，讓多分店客戶能由分店自行下單洗護、染膏、藥水等產品，並讓管理者統一查看、彙總、匯出所有分店訂單。

## 2) 系統定位

這套系統定位為「多分店內部訂購管理工具」，不是公開商城。

重點是：

- 分店下單要快。
- 管理者彙整要清楚。
- 品牌、品項、規格、價格、數量要結構化。
- 訂單可以依分店、品牌、品項、訂購期間彙總。
- 未來可以複製給不同美業品牌或連鎖門市。

## 3) 使用者角色

| 角色 | 權限重點 | 主要畫面 |
| --- | --- | --- |
| 管理者 | 管理商品、分店、價格、訂單狀態、匯出彙總 | 管理後台 |
| 分店帳號 | 建立自己分店的訂單、查看自己分店歷史訂單 | 分店下單入口 |
| 阿順 / Ewalk.ai 管理端 | 協助初始化商品資料、檢查客戶使用情況、處理異常 | 內部維護視角 |

## 4) MVP 範圍

### 這次要做

- 登入入口
- 管理者後台
- 分店下單頁
- 分店訂單紀錄
- 管理者訂單彙總
- 商品資料管理
- 分店資料管理
- 訂單狀態管理
- CSV / Excel 匯出

### 這次先不做

- 線上付款
- 發票開立
- 庫存扣帳
- 供應商自動下單
- 物流追蹤
- 複雜折扣活動
- App 版本
- 多語系

## 5) 核心流程

### 分店下單流程

1. 分店登入網站。
2. 進入「我要下單」。
3. 選擇訂購批次，例如 2026-06 第一批。
4. 依品牌或分類瀏覽商品。
5. 輸入訂購數量。
6. 系統自動計算小計與總金額。
7. 分店確認後送出訂單。
8. 系統鎖定訂單，分店可查看但不可任意修改。

### 管理者彙總流程

1. 管理者登入後台。
2. 查看本期所有分店訂單。
3. 依分店檢查是否已送出。
4. 依商品彙總總訂購量。
5. 匯出採購彙總表與分店明細表。
6. 將訂單狀態更新為已彙整、已採購、已到貨或已完成。

## 6) 必要功能

### 登入與權限

- 管理者與分店使用不同權限。
- 分店帳號只能看到自己的分店資料。
- 管理者可以看到所有分店。
- 所有訂單異動要保留建立時間、修改時間與操作者。

### 商品管理

商品欄位：

| 欄位 | 說明 |
| --- | --- |
| 品牌 | 例如 Inebrya、Fanatic F6、其他供應品牌 |
| 分類 | 洗髮、護髮、染膏、藥水、耗材 |
| 品項名稱 | 商品名稱 |
| 規格 | 容量、色號、包裝單位 |
| 單位 | 瓶、條、盒、組、包 |
| 價格 | 分店訂購價格 |
| 是否上架 | 停用品項可下架 |
| 備註 | 特殊訂購限制 |

### 分店管理

分店欄位：

| 欄位 | 說明 |
| --- | --- |
| 分店名稱 | 對內顯示名稱 |
| 店長 / 負責人 | 聯絡窗口 |
| 電話 | 聯絡方式 |
| 地址 | 到貨或內部辨識 |
| 帳號狀態 | 啟用 / 停用 |

### 訂單管理

訂單狀態建議：

| 狀態 | 說明 |
| --- | --- |
| 草稿 | 分店尚未送出 |
| 已送出 | 分店完成確認 |
| 已鎖定 | 管理者開始彙整，分店不可修改 |
| 已彙整 | 管理者完成總表 |
| 已採購 | 已交給總部或供應商採購 |
| 已到貨 | 商品已到貨 |
| 已完成 | 本批訂單結案 |
| 已取消 | 訂單取消，需留原因 |

## 7) 管理者儀表板

管理者首頁至少需要看到：

- 本期訂購批次
- 已送出分店數 / 全部分店數
- 本期總金額
- 本期總品項數
- 尚未下單分店
- 最近送出的訂單
- 可一鍵匯出總表

## 8) 彙總報表

### 商品彙總表

用途：給管理者或總部統一採購。

欄位：

- 品牌
- 分類
- 品項名稱
- 規格
- 單位
- 單價
- 各分店數量
- 總數量
- 總金額

### 分店明細表

用途：給各分店核對。

欄位：

- 分店
- 訂購批次
- 品牌
- 品項名稱
- 規格
- 單價
- 數量
- 小計
- 訂單狀態
- 送出時間

## 9) 建議技術路線

第一版建議採用：

- 前台 / 後台：Next.js 或同級網站框架
- 資料庫：Firebase Firestore
- 登入：Firebase Auth
- 檔案匯出：CSV / Excel
- 部署：Vercel

原因：

- 可以快速做出可登入網站。
- 適合多分店資料與權限分隔。
- Ewalk.ai 既有文件已有 Firebase Command Center 經驗，可銜接現有 SOP。
- 未來可再加自動通知、Discord 回報、Email 通知或供應商串接。

## 12) 驗收標準

- 分店登入後，只能看到自己的訂單。
- 分店可以建立一筆訂單，並輸入多個品項數量。
- 系統能正確計算每個品項小計與訂單總金額。
- 管理者能看到所有分店訂單。
- 管理者能依商品彙總全部分店數量。
- 管理者能匯出商品彙總表與分店明細表。
- 訂單送出後狀態清楚，不能被分店任意改動。
- 商品停用後不出現在分店下單清單。

## 13) 風險與權限

| 類型 | 風險 | 處理方式 |
| --- | --- | --- |
| 價格風險 | 商品價格變動造成歷史訂單金額錯誤 | 訂單項目需保存當下價格，不只連 productId |
| 權限風險 | 分店看到其他分店訂單 | Firestore 規則與後端檢查都要限制 storeId |
| 營運風險 | 分店送出後想修改 | 設計「管理者退回修改」流程 |
| 採購風險 | 管理者匯出前仍有分店未下單 | 儀表板顯示未送出分店 |
| 資料風險 | 商品資料一開始大量輸入容易錯 | 先用 CSV 匯入模板與人工抽查 |

## 14) 待補資料

- 客戶 / 品牌名稱
- 分店清單
- 商品清單
- 是否每個分店價格相同
- 是否需要不同品牌分開結帳或分開匯出
- 訂購週期是每週、每月，還是活動檔期制
- 分店送出後是否允許修改
- 管理者是否需要幫分店代下單
- 是否需要 Email / LINE / Discord 通知
- 是否需要供應商登入

2. 請客戶依 [[商品資料匯入模板.csv|商品資料匯入模板]] 與 [[分店資料匯入模板.csv|分店資料匯入模板]] 補資料。
3. 做一版可點擊網站原型，先確認分店下單流程順不順。
4. 確認登入與權限規則後，再進入工程實作。
5. 若試點成功，抽成「美業多分店訂購系統模板」，可複製給其他連鎖品牌。
