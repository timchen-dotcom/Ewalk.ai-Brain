# 交接單｜美業多分店內部訂購系統

## 任務背景

提姆先生提出要開發一套以網站為入口的內部訂購系統，讓多家分店可以訂購洗護、染膏、藥水等產品，管理者可以統整所有分店訂單。

## 交接來源

- 交出角色：阿順
- 接手角色：AI 自動化與知識管理部 / 工程實作角色 / 專案助理
- 交接日期：2026-05-24
- 客戶 / 專案：待確認，暫定為美業多分店內部訂購系統

## 已完成

- 已建立 MVP 需求規格。
- 已定義管理者與分店兩種核心角色。
- 已整理分店下單流程、管理者彙總流程。
- 已建立商品、分店、訂單、訂單明細與訂購批次的資料表草案。
- 已列出第一版畫面清單、驗收標準與風險。
- 已建立商品資料與分店資料 CSV 匯入模板。
- 已為 TheDay 那日美學建立可試用測試版，位置：[[../../01_客戶/TheDay那日美學/02_網站與系統/theday-order-test/README|TheDay 分店內部訂購測試版]]。

## 重要發現

- 這套系統不應先做成一般電商，而應先做成「內部訂購與採購彙總工具」。
- 第一版最重要的是權限隔離、商品資料正確、訂單彙總清楚。
- 訂單明細必須保存當下價格，避免商品價格更新後影響歷史訂單。
- 分店送出後是否可修改，會直接影響流程與客服成本，需提前決策。

## 缺少資料

- 客戶 / 品牌名稱
- 分店清單
- 商品清單
- 商品價格與規格
- 訂購週期
- 訂單送出後修改規則
- 是否需要通知功能
- 是否需要供應商或總倉角色

## 風險 / 待確認

- 客戶風險：若分店數量多，商品資料錯誤會造成大量訂單錯誤。
- 交付風險：若一開始加入庫存、物流、付款，MVP 範圍會過大。
- 成本風險：若需要完整後台、匯入匯出、通知與權限，工期需切階段估算。
- 權限風險：分店帳號不可看到其他分店訂單，這是第一版必測項目。

## 接手者下一步

1. 向提姆先生確認試點客戶與第一批分店數量。
2. 請客戶依 CSV 模板補商品與分店資料。
3. 製作網站低保真原型。
4. 用 1 個管理者、2 個分店、10 個商品跑完整下單測試。

## 需要阿順整合

- 將系統需求整理成客戶可看版本。
- 協助把試點結果抽成可複製案例。
- 協調工程、專案助理與提姆先生的決策點。

## 需要提姆先生批准

- 試點客戶與品牌名稱。
- 第一版是否使用 Firebase / Vercel 技術路線。
- 訂單送出後是否允許分店修改。
- 是否先做原型，還是直接進入 MVP 開發。
- 是否將此系統包裝成 Ewalk.ai 可販售的美業營運系統產品。
