# 0520 現場語音阿順運行方案

## 核心問題

目前語音阿順 Demo 是本機 Node 服務：

```text
Mac 本機 server
        ↓
http://127.0.0.1:4320
        ↓
瀏覽器使用麥克風與 GPT-Realtime-2
```

`127.0.0.1` 只代表「正在跑 server 的那台機器自己」。所以如果提姆當天只帶 iPad，iPad 不能直接連到家裡或辦公室 Mac 的 `127.0.0.1`。

## 最穩建議

### 方案 A：帶 MacBook 到現場當主機（最穩）

```text
MacBook 跑語音阿順 server
iPad / 現場螢幕開 MacBook 提供的網址
麥克風與喇叭接 MacBook
```

優點：

- 最接近目前已測成功的版本
- API key 不用放到雲端
- 現場問題比較好排除
- 可以保留離線 Q&A 備援

缺點：

- 需要帶 MacBook
- 現場要處理音訊輸入輸出

建議：如果這是第一次公開展示，優先用方案 A。

### 方案 B：部署雲端後端，iPad 直接開網址（最符合只帶平板）

```text
Vercel / 雲端 server
        ↓
iPad Safari 開公開網址
        ↓
iPad 麥克風收音
        ↓
GPT-Realtime-2 回答
```

優點：

- 當天只帶 iPad 就能跑
- URL 可以提前測試
- 不依賴現場有 MacBook

缺點：

- API key 要放到雲端環境變數
- 要確認 Realtime WebRTC 在 iPad Safari 可正常使用
- 現場網路變成關鍵風險
- 需要部署與測試時間

建議：如果提姆確定只帶平板，5/20 前必須至少提前 2-3 天部署並用同一台 iPad 彩排。

### 方案 C：iPad 用遠端連回 Mac（不建議當主方案）

例如遠端桌面、Tailscale、ngrok。

優點：

- 不一定要正式部署

缺點：

- 現場風險高
- 音訊路由容易出問題
- 網路延遲與權限問題比較多

只建議當臨時測試，不建議當大會主方案。

## 阿順建議

本次 5/20 是現場展示，不是技術發表。最重要是穩。

建議決策：

1. 若可以帶 MacBook：用方案 A。
2. 若一定只帶 iPad：立刻做方案 B，部署雲端版。
3. 不管選哪個方案，都要保留離線 Q&A 備援頁。

## 方案 A 現場操作

1. MacBook 先連網。
2. 雙擊 `開啟現場語音阿順.command`。
3. 打開 `http://127.0.0.1:4320`。
4. 接上麥克風與喇叭。
5. 測試 5 題必問問題。
6. 若失敗，打開 `public/offline.html` 播放備援 Q&A。

## 方案 B 現場操作

1. 事前部署到 Vercel 或其他雲端。
2. 在雲端設定 `OPENAI_API_KEY`。
3. 用 iPad Safari 開公開網址。
4. 允許麥克風權限。
5. 測試語音、喇叭、現場網路。
6. 若失敗，使用離線 Q&A 或預錄音檔。

## 必備備援

- 預設 5 題 Q&A
- 離線備援頁
- 預錄 3-5 段阿順回答
- 主持人照稿版本
- 手機熱點
