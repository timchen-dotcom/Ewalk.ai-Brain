# Ewalk.ai 客戶資料補齊盤點

建立日期：2026-05-23  
負責角色：阿順  
最終決策者：提姆先生  
狀態：第一版盤點完成，等待逐批補資料

## 目的

15 位客戶已正式匯入 Firestore `clients` collection。下一步不是直接自動發文，而是把每位客戶補到可以進 Command Center 管理的程度。

這份盤點用來決定：

- 哪些客戶可以優先複製韓食樣板。
- 哪些資料缺口會阻擋內容排程、Meta 串接或月報。
- 哪些動作需要提姆先生批准。

## 目前結論

第一優先批次建議放美業客戶，因為 Ewalk.ai 的社群內容、檔期活動、廣告投放與素材規劃最容易複製。

優先順序：

1. The Vision Hair Salon
2. TG hair salon
3. S.Color 芯 STAR Color
4. STAR SPA
5. 歐卡 OC HAIR VOGUE
6. KaDou 卡豆髮藝

韓食日常鍋物維持樣板客戶，繼續補正式 System User token、IG 串接與成效回收。

## 必補欄位

每位客戶要能進 Command Center，至少要補齊：

| 類別 | 欄位 | 用途 |
| --- | --- | --- |
| 客戶基本資料 | 正式名稱、產業、合作狀態、主要窗口 | 讓阿順與 AI 員工知道服務對象 |
| 社群資產 | FB 粉專、IG、LINE、Google 商家、官網 | 內容導流與成效回收 |
| Meta 串接 | Page ID、Business Portfolio、管理權限、是否可發文 | 判斷能不能走自動化 |
| 內容營運 | 內容支柱、品牌語氣、禁用語、每週頻率 | 產生月曆與貼文 |
| 服務與檔期 | 主力服務、價格區間、優惠、活動期限 | 避免文案寫錯承諾 |
| 素材 | Logo、品牌色、照片、影片、設計模板 | 交給設計企劃與圖像生成 |
| 廣告 | 是否投放、月預算、受眾、KPI | 廣告動作需提姆先生批准 |
| 審核 | 阿順初審、提姆先生終審、客戶是否需審 | 決定能否正式發布 |

## 安全邊界

本階段允許：

- 補 Obsidian 文件。
- 產生 dry-run JSON。
- 更新 Command Center 本機預覽。
- 讀取正式 Firestore 做回查。

本階段不做：

- 不呼叫 Meta API 發文。
- 不建立或保存 access token。
- 不改廣告預算。
- 不啟用 Blaze / billing。
- 不開放客戶入口。
- 不代客戶承諾優惠、價格或療效。
