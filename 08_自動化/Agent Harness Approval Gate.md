# Agent Harness Approval Gate

建立日期：2026-06-02  
負責角色：阿順  
最終決策者：提姆先生  
狀態：小公司可控版第一版

## 用途

Approval Gate 是阿順系統的批准閘。

它的目的不是讓流程變慢，而是讓 Ewalk.ai 可以放心自動化：

```text
低風險自動跑
中風險先產草稿
高風險等提姆先生批准
```

## 三種處理方式

| 類型 | 說明 | 阿順動作 |
| --- | --- | --- |
| 自動執行 | 低風險、內部整理、可回退 | 直接做，留紀錄 |
| 送審草稿 | 客戶看得見、品牌有影響，但尚未對外 | 產出草稿，送提姆先生審 |
| 必須批准 | 對外、金流、預算、核心規則、不可逆 | 停下，等提姆先生明確批准 |

## 必須批准清單

### 對外發布

- Facebook / Instagram 發文
- Reels / Shorts / YouTube 發布
- 客戶正式公告
- 網站正式上線
- 對外 Email / DM 正式送出

### 金流與訂閱

- 取消訂閱
- 升級 / 降級方案
- 改付款方式
- 刪除帳單或發票資料
- 開啟 Firebase Blaze 或其他付費服務

### 廣告與預算

- 新增廣告活動
- 啟用 / 停止廣告
- 調整預算
- 更改受眾、投放地區、出價策略

### 核心系統

- 修改 `AGENTS.md`
- 修改 Skill 長期規則
- 新增高權限外部工具
- 建立常駐自動化
- 開放 webhook 直接觸發工具
- 部署正式後端服務

### 客戶承諾

- 報價
- 合約
- 正式交期
- 服務範圍
- 對客戶承諾成效

## Approval Request 格式

阿順向提姆先生請示時，固定使用：

```md
# 批准請求

## 要批准什麼

## 為什麼要做

## 影響範圍

## 風險

## 不批准會怎樣

## 可回退方式

## 阿順建議
批准 / 不批准 / 修改後再做
```

## Approval 狀態

| 狀態 | 意義 |
| --- | --- |
| `not_required` | 不需要批准 |
| `pending` | 等待提姆先生批准 |
| `approved` | 已批准，可執行 |
| `rejected` | 不批准 |
| `changes_requested` | 需修改後再送審 |
| `expired` | 批准已過期，需要重新確認 |

## 批准有效期

| 類型 | 有效期 |
| --- | --- |
| 單篇貼文 | 僅本次 |
| 單次網站部署 | 僅本次 |
| 單次訂閱調整 | 僅本次 |
| 固定每日摘要 | 可一次批准長期執行 |
| 固定低風險資料整理 | 可一次批准長期執行 |
| 任何金流 / 廣告預算 | 不可長期 blanket approval，需逐次確認或設定明確上限 |

## 阿順執行規則

阿順可以先做：

- 草稿
- 分析
- 排程建議
- 發文預覽
- 預算建議
- 訂閱取消建議
- 客戶回覆草稿

阿順不能自行做：

- 真的發出去
- 真的扣款
- 真的改預算
- 真的取消
- 真的刪除
- 真的改核心規則

## 與 `ai_runs` 的關係

每次任務都要標記：

```json
{
  "approval_required": true,
  "approval_status": "pending",
  "approval_id": "approval_20260602_001"
}
```

如果提姆先生批准，任務才進入可執行狀態。

## 小公司可控版判斷

第一階段不用做複雜企業權限系統。

先做到：

- 哪些任務要停
- 停下來問誰
- 問的格式固定
- 批准紀錄可回查
- 沒批准就不動作

這樣就能讓阿順開始分擔大量工作，同時不越權。
