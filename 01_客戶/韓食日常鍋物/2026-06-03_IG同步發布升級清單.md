Instagram API 需要：

1. IG 專業 / 商業帳號。
2. IG 帳號連結到韓食日常鍋物 Facebook Page。
3. Meta App / System User 具備 IG 發布權限。
4. 先建立 IG media container，再呼叫 `media_publish`。
5. 圖片必須能被 Meta 以公開 URL 讀取，不能只給本機檔案路徑。

## 圖片尺寸決策

FB / IG 動態主圖統一：

```text
1080 x 1350
比例：4:5
用途：Facebook / Instagram feed 共用
```

原因：

- IG feed 支援 4:5 直式圖。
- FB feed 可使用 4:5 圖，不影響正式發布。
- 對餐飲內容來說，4:5 比 1:1 更有版面空間，食物與文字層級更好安排。

輸出規格：

- 內部主檔：PNG 可保留。
- IG API 發布檔：建議輸出 JPEG。
- IG 圖檔需控制在 API 規格內，並放到公開圖片 URL。

## 工具改造方向

目前 Facebook：

```text
本機圖片 → Graph API /{page-id}/photos → FB Post ID
```

IG 需要：

```text
本機圖片 → JPEG 1080x1350 → 公開圖片 URL
公開圖片 URL + caption → /{ig-user-id}/media → container ID
container ID → /{ig-user-id}/media_publish → IG Media ID
IG Media ID → 回寫佇列與成效追蹤
```

## 發布策略

建議分三階段：

### Stage IG-1：視覺先統一

- 從今天起，所有 FB / IG 動態共用圖都做 1080x1350。
- caption 可先沿用 FB，但 IG hashtag 可由社群主編另補短版。

### Stage IG-2：半自動同步

- FB 由現有工具自動發布。
- IG 先由社群自動化發文員產生 IG 發布包。
- 人工確認 IG 帳號與版面無誤後發布。

### Stage IG-3：全自動同步

- FB 發布成功後，同一篇內容同步呼叫 IG API。
- 兩邊各自回寫 Post ID / Media ID。
- 成效追蹤員分平台建檔。

## 風險提醒

- IG API 對圖片 URL、檔案格式、比例與容器有效期限較嚴格。
- container 有時需要等待處理完成，不適合無限重試。
- IG caption 長度、hashtag、@tag 有平台限制，不能直接無腦套 FB 長文。
- IG 帳號若仍未完成商業帳號與粉專連結，不得硬上同步發布。
