## 2. 加盟資訊系統總覽

一句話：

> 從總部營運、門店執行、會員互動到獎金分潤，形成可管理、可追蹤、可擴張的加盟數位平台。

主要架構：

```text
雲端資料與 API 服務層
→ GADM 總部中心
→ OPS 店家端
→ CSM 會員端
→ 獎金分潤系統
→ 外部支援與營運周邊
```

雲端資料集中管理：

- 加盟資料
- 門店資料
- 會員資料
- 交易資料
- 庫存資料
- 分潤資料

## 3. 三端加盟管理 App

### GADM｜總部中心

定位：總部治理與多店管理。

功能：

- 訂閱與點數
- 員工與抽成設定
- 多店鋪管理
- 商品 / 票券 / 庫存
- 薪資與營收報表

### OPS｜店家端

定位：店務執行與交易流程。

功能：

- 個人排班
- 訂單管理
- 業績統計
- 統計報表
- 庫存與票券管理

### CSM｜會員端

定位：會員服務、預約、優惠與消費紀錄。

功能：

- 一鍵預約
- 專屬優惠推播
- 個人檔案
- 消費與造型紀錄
- 信賴店家串聯

### 整合關係

```text
GADM 建立店家、員工、商品、票券、抽成規則
→ OPS 依店家與員工權限執行開單、核銷、庫存與業績
→ CSM 將會員預約、優惠、消費紀錄回寫雲端
→ 交易與月結資料匯入獎金分潤系統進行結算
```

核心概念：

可視覺化架構：

## 5. 獎金分潤系統

定位：

> 將店數、層級、月盈餘、產品費、管理費轉換為可稽核、可月結、可追溯的財務資料。

### 核心結算規則

| 項目 | 規則 |
|---|---|
| 開發成功單店一次性獎金 | `30,000 元` |
| A 代 | 一代店 / 技術營運傳承獎金 |
| B 代 | 二代店，每月盈餘 `5%` |
| C 代 | 三代店，依兩代分潤制度核算 |
| 組織領導紅利 | 主任 `1%`、經理 `2%`、部長 `3%` |
| 技術組織管理費 | 主任 `1%`、經理 `1.5%`、部長 `2%` |
| 區域小總部產品費後退 | 經理 `5%`、部長 `10%` |
| 管理基金 | 每單店盈餘 `2.5%` |

### 必要模組

- 加盟組織樹
- 月結資料匯入
- 分潤規則引擎
- 審核與簽核
- 報表與撥款

## 7. 生成限制

- 分潤比例與獎金數字不可改。
- 不要寫成保證收益。
- 財務與分潤要使用「規則、試算、月結、稽核」語氣。
- 若直接生成圖像，分潤表不要過度密集，改用 3–5 個重點卡。
