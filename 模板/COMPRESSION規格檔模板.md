# COMPRESSION 規格檔模板（Context 壓縮規格）

用途：當任務變長、context 變雜時，用「可回歸的規格」決定何時壓縮、保留什麼、丟掉什麼，避免壓縮後把規則/交付格式壓掉。

使用時機：

- 任務超過 30 分鐘或跨多階段（需求 → 設計 → 實作 → 驗證）
- 同一條流程常出現「越跑越慢、越跑越亂、越跑越貴」
- 需要交接給另一個 agent / 子角色時

---

## 來源

- COMPRESSION.md（spec 概念）：https://compression.md/

---

## 壓縮觸發條件（Triggers）

至少滿足一項就觸發：

- `context_used_ratio >= 0.75`
- 同一任務連續出現「重複讀檔/重複確認/重複列工具」3 次以上
- 開始偏題：輸出與任務目標不一致 2 次以上

---

## 永遠保留（preserve_always）

> 這段是壓縮後仍必須完整保留的「不可壓縮核心」。

- 任務目標（1 句話）
- 交付格式（必填區塊、檔名、路徑、標題）
- 權限/風險邊界（哪些不能做、哪些要提姆先生批准）
- 目前進度與卡點（含錯誤訊息/失敗原因）
- 待辦清單（下一步 3–7 條）
- 重要證據連結（來源 URL / 檔案路徑 / commit/issue 連結）

---

## 可大幅壓縮（compress_aggressively）

- 已完成的探索過程（嘗試過的關鍵字、無效方向）
- 中間推理與長篇討論（只留結論）
- 重複的背景介紹（保留一次即可）

---

## 目標輸出（Compression Targets）

- `target_compression_ratio`: `0.50`（把可壓縮內容壓到原本的一半）
- `max_summary_length`: `400–800` 字（依任務複雜度調整）

---

## 壓縮後的「交接摘要」格式（建議）

```md
## 任務目標
- 

## 必須保留的規則（不可壓縮）
- 

## 目前進度
- 

## 重要證據（來源/檔案）
- 

## 下一步（3–7 條）
1. 
2. 
3. 
```

---

## 驗收標準

- 壓縮後仍能 1 分鐘內理解「要做什麼、做到哪、下一步是什麼」
- 不遺失交付格式與權限邊界
- 後續 1–2 個階段的輸出品質不退化（至少不比壓縮前更偏題）

---

## 壓縮後必跑驗證（Post-compression Validation）

> 目的：避免「摘要看起來很像」但其實把交付條件/承諾/約束省掉。

- [ ] `preserve_always` 內每一項都還在（任務目標 / 交付格式 / 權限邊界 / 進度卡點 / 下一步 / 證據連結）
- [ ] 交付格式可直接照做（檔名規則、資料夾路徑、必填段落都存在）
- [ ] 權限/風險邊界仍清楚（哪些不能做、哪些要提姆先生批准）
- [ ] 重要數字/結論仍可追溯（至少 1 個 raw 證據：URL / 檔案路徑 / issue / commit）
- [ ] 下一步（3–7 條）可執行且不跳步（先研究/確認 → 再改動 → 再驗證）
- [ ] 若是推理/決策型任務：列出「不可違反承諾」清單（3–7 條），並在壓縮後再次確認仍保留
