# Google 評論每日追蹤 SOP

## 用途

讓阿順每日追蹤所有代管客戶的 Google 評論，確認新增評論、未回覆數量、回覆期限、到期倒數與提醒狀態。

## 使用時機

- 每日早上例行檢查客戶 Google 評論。
- 客戶要求 Ewalk.ai 協助管理 Google 商家聲量。
- 月報需要整理評論回覆率與服務風險。
- 負評、客訴或逾期未回覆需要升級提醒。

## 權限邊界

- 可自動讀取評論、統計、產生報表、發送提醒。
- 可產出回覆草稿，但不能自動送出。
- 對外回覆、刪除回覆、修改商家資料、處理爭議評論前，需要提姆先生或客戶批准。

## 前置資料

1. 客戶已授權 Ewalk.ai 或指定管理帳號管理 Google Business Profile。
2. Google Cloud 專案已啟用 Business Profile 相關 API。
3. OAuth 已取得 `business.manage` scope 的 refresh token。
4. `Ewalk.ai Brain/08_自動化/Google評論每日追蹤系統/clients.csv` 已填入客戶與分店。
5. `config.local.json` 已設定 `google_review_tracker`、`enabled: true` 與 Discord webhook。

## 每日流程

1. 系統於每日 09:30 執行追蹤。
2. 讀取啟用中的客戶與分店。
3. 抓取各 Google 商家評論。
4. 比對本地狀態，判斷是否有新增評論。
5. 統計未回覆評論、今天到期、已逾期。
6. 依品牌語氣產生建議回覆草稿。
7. 產生 Markdown 與 JSON 報表。
8. 將摘要送到 Discord `#客戶待辦`。
9. 若有今天到期或逾期，另外送到 `#重要提醒`。
10. 客戶成功經理或指定負責人確認回覆草稿與處理狀態。

## 回覆期限規則

| 評論類型 | 建議 SLA |
| --- | --- |
| 1 至 2 星負評 | 1 天內 |
| 3 星中性評論 | 2 天內 |
| 4 至 5 星正評 | 3 天內 |
| 高風險評論 | 1 天內，人工審稿 |

若 `clients.csv` 已設定 `sla_days`，以客戶設定為準。

## 回覆草稿流程

1. 從每日報表複製評論摘要。
2. 使用 [[../11_Prompt資料庫/Google評論回覆追蹤Prompt|Google 評論回覆追蹤 Prompt]] 產生草稿。
3. 正評可由客戶成功經理初審。
4. 負評、爭議、個資、醫療、法律、金流或品牌風險評論交給提姆先生確認。
5. 客戶或授權人到 Google 商家後台送出回覆。
6. 隔日追蹤確認該評論已從未回覆清單移除。

## 報表位置

每日報表存放於：

`Ewalk.ai Brain/04_報表/Google評論追蹤/YYYY-MM-DD.md`

JSON 結構化資料存放於同一資料夾，可供未來接 Command Center 或月報統計。

## 異常處理

| 狀況 | 處理 |
| --- | --- |
| API 無法讀取某分店 | 檢查該客戶是否授權管理權限 |
| OAuth 失效 | 重新授權並更新 refresh token |
| API 評論數與前台不同 | 記錄差異，第一週人工複查 |
| Discord 沒收到 | 檢查 `config.local.json` webhook |
| 逾期仍未回覆 | 每日升級提醒，並列入客戶待辦 |

## 驗收標準

- 每日報表有追蹤分店、新增評論、未回覆數、今天到期、逾期數。
- 每則未回覆評論有建立日、到期日、倒數、客戶、分店、摘要與建議回覆草稿。
- Discord 摘要可讓負責人不用開報表也知道是否有急件。
- 不會把首次歷史評論誤判為今日新增。
- 不會自動替客戶對外發文或回覆。

## 可升級方向

- 串接 Google Pub/Sub `NEW_REVIEW` 做即時提醒。
- 在 Command Center 顯示客戶評論 SLA 看板。
- 月報自動統計評論新增數、回覆率、平均回覆天數。
- 依星等自動套用不同回覆草稿流程。
