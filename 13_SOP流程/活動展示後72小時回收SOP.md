# 活動展示後 72 小時回收 SOP

## 目的

讓 Ewalk.ai 在完成客戶活動、現場展示、Demo 發表、課程或出差任務後，能在 72 小時內把現場成果收回成可追蹤行動、客戶後續、案例素材與系統升級候選，避免展示結束後只留下零散待辦。

## 使用時機

- 客戶提案、創業大會、加盟說明會、現場 Demo 結束後
- 提姆先生出差或現場教課回來後
- 有現場展示工具、簡報、語音阿順、網站 Demo 或 AI 系統原型時
- 每日工作筆記連續出現「展示後續」「回饋待整理」「下一次溝通重點」時

## 輸入資料

- 活動前最終版交付物與歸檔紀錄
- 活動當日每日工作筆記
- 活動後 1 至 3 天每日工作筆記
- 客戶回饋、現場問答、未回覆事項
- Demo / 簡報 / 網站 / 自動化工具的實際使用狀態
- Discord、LINE、Email 或會議紀錄中的後續交辦

## 72 小時流程

### 1. 24 小時內：鎖定事實與版本

- 確認活動日期、地點、客戶與參與角色。
- 確認當天實際使用的簡報、網站、Demo、講稿或備援版本。
- 標註哪些文件是最終版，避免後續拿錯版本。
- 記錄現場有沒有成功展示、臨時改動、技術問題或客戶反應。

### 2. 48 小時內：整理後續行動

建立一份活動後續行動清單，至少包含：

| 欄位 | 說明 |
| --- | --- |
| 事項 | 要追蹤的具體任務 |
| 對象 | STAR Color / TG / OC / 其他客戶或內部角色 |
| 責任角色 | 阿順、專案助理、社群主編、設計企劃、數據分析師、提姆先生 |
| 狀態 | 待整理 / 待回覆 / 進行中 / 待批准 / 已完成 |
| 截止日 | 若沒有日期，先標「待確認」 |
| 需要提姆先生批准 | 是 / 否 |
| 證據連結 | 對應文件、簡報、Demo、訊息或會議紀錄 |

### 3. 72 小時內：分類成四種資產

| 分類 | 放置位置 | 判斷標準 |
| --- | --- | --- |
| 客戶後續 | `01_客戶/客戶名稱` | 需要回覆客戶、追加交付、補資料或排下一次會議 |
| 每日待辦 | `14_每日工作` | 需要本週執行或追進度 |
| 案例候選 | `12_案例庫` | 可變成銷售案例、招商案例、Demo 成功案例 |
| 系統升級候選 | `09_知識庫/自我升級情報` 或 `13_SOP流程` | 可重複使用的流程、模板、Prompt、風險規則 |

## 標準輸出

活動後至少產出一份「活動後續行動清單」。若活動有重大成果，再加產：

- 客戶回覆草稿
- 下一次會議重點
- 案例候選摘要
- SOP / Prompt / 自動化升級候選

## 文件命名

建議放在對應客戶資料夾：

```text
YYYY-MM-DD_活動名稱_展示後續行動清單.md
```

```text
2026-05-20_STAR_Color創業大會_展示後續行動清單.md
```

## 權限與風險

- 對外回覆、追加報價、承諾交付日期、調整廣告預算、正式發文與金流事項，需提姆先生批准。
- 現場 Demo 若涉及 API key、客戶資料、登入權限或付費服務，必須標註風險與備援方案。
- 活動後摘要不能取代原始證據；簡報、錄音、訊息、截圖與部署網址應保留原始位置。

## 驗收標準

- 活動後 72 小時內有一份可追蹤的後續行動清單。
- 每個後續事項都有責任角色、狀態與下一步。
- 可沉澱的案例與 SOP 候選已被標出。
- 需要提姆先生批准的事項沒有被自動執行。
