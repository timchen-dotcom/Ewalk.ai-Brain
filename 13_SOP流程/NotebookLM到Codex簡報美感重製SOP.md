# NotebookLM 到 Codex 簡報美感重製 SOP

## 目的

解決 Codex 直接生成簡報時美感不足的問題。讓 NotebookLM、參考簡報或高品質截圖負責建立視覺基準，Codex 負責內容結構、可編輯檔案、品牌一致性與最終交付。

## 核心判斷

Codex 的強項是資料整理、結構化、檔案產出、自動化與可重複流程；NotebookLM 的強項是資料 grounded、來源引用與視覺化輸出。兩者不要互相取代，而是分工。

最佳流程：

```text
資料來源 / PDF / 網頁 / 影片
        ↓
NotebookLM 建立研究與初版視覺簡報
        ↓
匯出 PDF / 截圖 / 文字大綱
        ↓
Codex 拆解版型與敘事
        ↓
Codex 用簡報工具重製成可編輯 PPTX
        ↓
阿順做品牌、文字、來源與美感檢查
```

## 使用時機

- 客戶提案簡報
- 月報與成效回顧
- 課程簡報
- 趨勢週報轉簡報
- 品牌教育材料
- 對外分享、招商、加盟、簡報型銷售材料

## 不建議的做法

- 不讓 Codex 從零開始自由設計簡報。
- 不接受預設工程師風 dashboard 版型。
- 不把大量文字直接塞進投影片。
- 不用單色系、厚卡片、過多邊框、過密資訊表當主視覺。
- 不只檢查內容正確，也要檢查是否像真正給客戶看的簡報。

## 推薦工作流

### 1. 先建立視覺基準

至少提供其中一種：

- NotebookLM 產出的簡報 PDF 或截圖
- 參考簡報
- 品牌規範
- 客戶 IG / 官網 / DM 視覺
- 3-5 張你覺得好看的簡報頁截圖

阿順要先回答：

- 這份簡報應該像哪個品牌？
- 主色、輔色、留白、字體感、圖片風格是什麼？
- 每頁平均字數應該控制在哪裡？
- 是銷售型、教育型、報告型，還是品牌型？

### 2. 用 NotebookLM 做研究與初版

NotebookLM 適合做：

- 讀來源資料
- 保留引用
- 產生研究摘要
- 產生初版簡報邏輯
- 提供漂亮的視覺參考

但 NotebookLM 的輸出不一定適合直接交付，因為後續可能需要：

- 品牌化
- 調整商業說服順序
- 改成可編輯 PPTX
- 套入 Ewalk.ai 或客戶的語氣

### 3. Codex 只做可控重製

Codex 的任務：

- 拆解 NotebookLM 的版型與敘事
- 保留來源連結與引用
- 把內容轉成可編輯 PPTX
- 套用品牌與商業邏輯
- 產生交付說明

Codex 不應自由發揮視覺，除非提姆明確要求。

### 4. 每頁都做美感驗收

每頁檢查：

- 這頁一句話重點是什麼？
- 是否有足夠留白？
- 字是否太多？
- 圖片是否真的有幫助？
- 版面是否像客戶願意看的簡報？
- 是否保留來源或可追溯資料？

## 交付標準

- PPTX 可編輯
- 另存一份 PDF 預覽
- 來源連結完整保留
- 每頁有清楚主訊息
- 用字白話、商業可用
- 視覺至少達到 NotebookLM 參考稿的 80% 質感
- 若達不到，不能假裝完成，要回報需要更多參考或改用 NotebookLM 原稿做基準

## 阿順判斷規則

- 如果任務重視美感：先用 NotebookLM / 參考圖建立基準。
- 如果任務重視可編輯與交付：Codex 重製。
- 如果任務重視快速分享：可先給 NotebookLM PDF，再安排 Codex 重製。
- 如果是重要客戶提案：一定要有人眼檢查截圖，不只看檔案是否產出。

## 常用指令

```text
請不要直接從零生成簡報。先以 NotebookLM 產出的 PDF / 截圖作為視覺基準，拆解它的版型、留白、字級、節奏與圖片使用方式，再重製成可編輯 PPTX。
```

```text
請把這份資料整理成 NotebookLM 可讀的來源包與簡報大綱，目標是先讓 NotebookLM 產出視覺參考稿，再由 Codex 做品牌化與可編輯重製。
```

```text
請檢查這份 Codex 產出的簡報是否太工程師味。若是，請列出每頁需要修的美感問題，包含字太多、留白不足、層級不清、圖片不夠、色彩單調、像報表而不像簡報等。
```
