# 阿順自我優化 SOP

## 目的

讓阿順定期從實際工作中學習，把零散經驗沉澱成規則、SOP、Prompt、案例與知識，避免每次任務都從頭教。

## 使用時機

- 每週固定整理一次
- 完成大型客戶專案後
- 發現同一類任務重複出現時
- 阿順分類、命名、輸出格式出現不穩定時
- 看到外部教學、影片、文章，有可吸收的方法時
- 使用者輸入 `/自我升級` 並提供文章、YouTube、影片、PDF、圖片或文件時
- 每日 GitHub / 開源自我升級情報中出現高價值內容，且提姆允許吸收時

- `AGENTS.md`

## 執行步驟

### 1. 盤點最近工作

- 檢查收件匣中尚未分類的資料
- 找出最近新增或修改的客戶資料
- 找出重複出現的工作類型
- 標記可以抽成 SOP、Prompt 或案例的內容

### 2. 分類可沉澱資產

- 方法論、判斷準則：放 `09_知識庫`
- 市場或消費者洞察：放 `10_市場洞察`
- 可複用指令：放 `11_Prompt資料庫`
- 成功或失敗經驗：放 `12_案例庫`
- 標準流程：放 `13_SOP流程`
- 自動化規則：放 `08_自動化`

### 3. 更新阿順規則

需要時更新：

- `AGENTS.md`
- `Ewalk.ai Brain/08_自動化/阿順交辦規則.md`
- `Ewalk.ai Brain/00_系統說明/系統使用規則.md`
- 對應的 SOP 或 Prompt 文件

更新原則：

- 只加入已經反覆出現、值得固定的規則
- 不把一次性的例外寫成永久規範
- 每次更新保持簡短，避免規則太膨脹
- 每日 GitHub 情報只能提出升級建議；沒有提姆允許，不直接改全域規則

### 4. 建立下一步清單

輸出一份簡短清單：

- 本次新增或修改的文件
- 尚待確認的分類
- 建議下一個要 Skill 化的流程
- 需要使用者決策的事項

## 驗收標準

- 至少整理出一個可重複使用的規則、Prompt、SOP 或案例
- 文件放置位置正確
- 不破壞既有命名與資料夾結構
- 使用者能看懂這次優化帶來的具體幫助
