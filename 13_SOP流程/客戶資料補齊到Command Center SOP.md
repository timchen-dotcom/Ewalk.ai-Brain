# 客戶資料補齊到 Command Center SOP

建立日期：2026-05-23  
負責角色：阿順  
最終決策者：提姆先生  
適用範圍：Ewalk.ai 客戶從 Obsidian 名冊進入 Firebase Command Center

## 使用時機

當客戶已經出現在 `Ewalk.ai Brain/01_客戶`，但還不能進內容排程、Meta 串接或月報追蹤時，使用這份 SOP。

## 目標

把客戶從「資料夾存在」整理成「可管理、可排程、可審核、可追蹤」的營運狀態。

## 標準步驟

1. 確認客戶已存在 `clients` collection。
2. 檢查客戶資料夾是否有 `00_客戶總覽.md`。
3. 補齊社群資產：FB、IG、LINE、Google 商家、官網。
4. 補齊品牌資料：定位、語氣、服務、價格區間、禁用語。
5. 補齊內容欄位：內容支柱、每週頻率、檔期活動、素材路徑。
6. 補齊權限欄位：Meta Page ID、Business Portfolio、管理員、IG 串接狀態。
7. 補齊審核欄位：阿順初審、提姆先生終審、客戶是否需審。
8. 建立該客戶的 `Meta自動發文佇列.md`，先使用 dry-run。
9. 產生 Command Center dry-run。
10. 交給提姆先生批准是否正式寫入待發布佇列。

## 批准關卡

以下動作必須提姆先生批准：

- 正式寫入 Firestore 任務佇列
- 正式呼叫 Meta API 發文
- 啟用 System User token 或長期憑證
- 設定廣告預算
- 開放客戶入口
- 啟用付費雲端資源

## 檢查標準

- 客戶資料能被未來的阿順讀懂。
- 每個社群貼文都能追到來源、素材、審核與發文狀態。
- 缺資料不會被包裝成已確認事實。
- 有風險的內容會回到提姆先生批准。
- dry-run 與正式寫入要分清楚。
