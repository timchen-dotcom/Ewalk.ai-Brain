# 社群與廣告成效追蹤啟動 SOP

建立日期：2026-05-16  
主管：阿順  
負責職員：成效追蹤員  
狀態：已建立，先做紀錄，不要求每日回報

## 目的

只要有客戶開始自動化發社群或自動化投放廣告，Ewalk.ai 必須立刻建立追蹤紀錄，避免內容發出去了但後續沒有數據可查。

第一階段重點不是每天回報，而是讓每一篇貼文、每一組廣告都有可追溯的紀錄。

## 啟動條件

任一條件成立就啟動：

- FB / IG / Threads / Google 商家貼文由工具、自動化流程或排程發布
- Meta / Google / TikTok / LINE 廣告由工具、自動化流程或排程上線
- 發文或廣告工具回傳正式 ID
- 阿順建立新的社群或廣告自動化試點

## 權責分工

| 角色 | 負責 |
| --- | --- |
| 阿順 | 判斷是否啟動追蹤、分派成效追蹤員、確認是否需要提姆先生批准 |
| 成效追蹤員 | 建立追蹤紀錄、保存 ID 與追蹤節點、標記待補權限 |
| 社群主編 | 提供文案、素材、貼文目的與 CTA |
| 廣告投放專員 | 提供 Campaign / Ad Set / Ad ID、預算與投放目標 |
| 數據分析師 | 使用追蹤資料做週報、月報或優化建議 |

## 標準流程

1. 發文或廣告上線後，取得正式 ID。
2. 成效追蹤員在客戶紀錄或全公司追蹤總表新增任務。
3. 填入客戶、平台、類型、發布時間、素材、文案、ID。
4. 設定追蹤節點：1 小時、24 小時、72 小時、7 天。
5. 標記資料來源與待補 API 權限。
6. 不做每日回報，除非阿順或提姆先生指定。
7. 到週報或月報時，交給數據分析師整理洞察。

## API 資料來源

Meta 社群貼文常見來源：

```text
GET /{post-id}?fields=permalink_url,shares,comments.summary(true),reactions.summary(true)
GET /{post-id}/insights
GET /{page-id}/insights
```

Meta 廣告常見來源：

```text
GET /act_{ad_account_id}/insights
```

常見權限：

- `pages_read_engagement`
- `read_insights`
- `ads_read`

## 不做的事

- 不把 token、密鑰、App Secret 寫進 Obsidian
- 不每天主動回報，除非指定
- 不自行調整廣告預算
- 不把短期數據包裝成正式結論

## 驗收標準

- 每個自動化貼文或廣告都有一筆追蹤紀錄
- 每筆紀錄能回到原始素材、文案與發布 ID
- 追蹤節點明確
- 後續可交給數據分析師做月報
