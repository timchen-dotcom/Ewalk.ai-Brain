# Codex 長上下文卡住處理 SOP

建立日期：2026-05-18
負責角色：阿順

## 用途

當 Codex 視窗出現長時間「正在思考」、連線重試、上下文長期滿格，或任務一直重複跑時，用這份 SOP 快速停損。

## 判斷條件

符合任一項就不要再要求原視窗繼續：

- 顯示 `Reconnecting...` 多次後仍在思考。
- 下方上下文長期滿格，且「上下文已自動精簡」反覆出現。
- 同一個任務已經重複執行兩次以上。
- 代理開始反覆說「我再檢查一次」「我再重新生成一次」，但沒有新的明確結果。
- 任務明明已經有結論，卻又回到舊問題重新推理。

## 原因

長上下文視窗不等於一般乾淨新對話。自動精簡只會把舊內容壓成摘要，並不會真的清空整個視窗的任務慣性。

當同一個視窗已經塞進大量截圖、檔案、搜尋結果、建置輸出與反覆推理時，代理容易同時看見舊目標與新指令，造成以下問題：

- 把已經修正的問題當成還沒修。
- 反覆重跑同一個建置或檢查。
- 為了補齊資料而擅自延伸任務。
- 每次回合都消耗大量 token。

## 停損流程

1. 按下原視窗停止。
2. 不要在原視窗輸入「繼續」。
3. 開新 Codex 視窗，使用同一個工作資料夾。
4. 貼上乾淨的救援提示詞。
5. 要求新視窗只讀必要檔案、只跑一次檢查。
6. 若缺資料，列缺口後停止，不要補資料、不重跑。

## 救援提示詞模板

```text
請不要沿用舊視窗的推理。

任務：只重新讀取必要檔案並做一次健康檢查。

請讀取：
- AGENTS.md
- 相關 SOP
- 相關 Prompt
- 主要資料檔
- 主要建置或檢查腳本

規則：
1. 只跑一次檢查。
2. 不要自行補資料。
3. 不要重複生成。
4. 如果資料不足，列出缺口後停止。
5. 回報：目前狀態、發現問題、是否需要提姆先生補資料。
```

## 完成標準

- 原卡住視窗已停止。
- 新視窗只執行一次必要檢查。
- 任務結果可以用一句話判斷是否成功。
- 若有缺口，已列出需要提姆先生補的資料。
