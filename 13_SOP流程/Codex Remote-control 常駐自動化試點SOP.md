# Codex Remote-control 常駐自動化試點 SOP

## 目的

用「小範圍、可回滾」方式，把固定流程試做成 Codex app-server 常駐 + 遠端控制的形態，提升穩定性與可維運性。

## 使用時機

- 想把某條流程從「一次性執行」改成「可控服務」（可重啟、可觀測、可回放）
- 流程具有固定節奏（例如每日 04:00 情報蒐集）

## 試點範圍（建議）

第一條只做：

- [[../09_知識庫/自我升級情報/README|自我升級情報]]：每日情報蒐集 → 產檔 → 通知

## 試點設計原則

- 不改動既有「輸出格式、檔案路徑、Discord 通知內容」
- 先做到「可重啟」與「可追蹤失敗原因」
- 失敗就回退到原本一次性流程（不要卡住每日交付）

## 2026-06-04 補充：長任務治理驗收點

6 月初的 Codex 更新重點，已經不只是「能不能開 app-server」，而是能不能把長任務當成可治理服務來跑。之後做試點時，除了成功產檔，還要多看這 4 件事：

- 任務封存：已完成或失敗的 thread，是否能明確 `archive / unarchive`，避免舊任務污染新任務。
- 任務恢復：中斷後是否知道要接哪個 thread、缺什麼上下文、是否有草稿可回看。
- 身分分離：若未來要用 `CODEX_API_KEY` 或等價 access token 跑排程，必須把「人工作業身分」與「排程身分」拆開，不共用高風險權限。
- 狀態可觀測：至少要看得到 app-server 狀態、thread 狀態、MCP 連線狀態與最後失敗原因。

如果這 4 件事做不到，就算能常駐，也只算「能跑」，不算「能治理」。

## 操作步驟（概念版）

> 注意：不同 Codex 版本命名不同。若你的 Codex 版本已提供 `codex remote-control`，優先用它；否則用 `codex app-server` 走等價試點。

### 1) 定義回歸案例

- 以「每日情報」當回歸案例：能在本 Vault 寫出當日檔案、並產生一段 Discord 通知草稿

### 2) 常駐化（試點）

- 啟動 app-server 並保留：
  - 啟動/關閉方式（建議用腳本）
  - 日誌位置（至少要能看到錯誤原因）
  - 重啟策略（手動即可，先不做自動重啟）

本機快速指令（可直接用；二擇一）：

**A. `remote-control`（優先）**

- 啟動：`codex remote-control`（或依你版本的等價命令）
- 連線：`codex --remote ws://127.0.0.1:8787`

**B. `app-server`（等價替代）**

- 啟動：`Ewalk.ai Brain/08_自動化/本地AI-Gemma/scripts/start_codex_app_server.sh`
- 狀態：`Ewalk.ai Brain/08_自動化/本地AI-Gemma/scripts/codex_app_server_status.sh`
- 停止：`Ewalk.ai Brain/08_自動化/本地AI-Gemma/scripts/stop_codex_app_server.sh`

連線方式（另一個終端機）：

- `codex --remote ws://127.0.0.1:8787`

### 常見阻塞：`Operation not permitted (os error 1)`

若在啟動 app-server 時直接出現 `Operation not permitted`，代表目前的 Codex 安裝方式/沙盒限制無法開 listener（常見於 app 內建的 CLI）。

處理方式（擇一）：

- 改用「可更新、非沙盒限制」的 Codex CLI 安裝方式（依官方指引安裝後再跑本 SOP）
- 或先暫緩常駐化，維持一次性流程，直到試點環境可跑起 app-server

### 3) 驗收

- 連續 7 天（或至少 3 次）都能成功產檔
- 失敗時能快速定位（是網路、是權限、是工具列、是寫檔）
- 任務結束後能清楚判斷：要封存、保留待續跑、還是直接回退到一次性流程

### 4) 長任務治理檢查（新增）

每日或每次回歸至少補看一次：

- 是否保留當次輸出檔案與 Discord 草稿
- 若常駐失敗，是否有明確 thread / log 可回看
- 若要重跑，是否知道會不會重複寫入或重複通知
- 若要交接給提姆先生，是否能一句話說清楚「卡在哪、怎麼恢復」

## 驗收標準

- 成功率 ≥ 90%（7 天至少 6 天成功）
- 失敗定位時間 ≤ 10 分鐘（有日誌、有明確錯誤）
- 能一鍵回退到原本流程
- 能區分「這次是服務可用性問題」還是「這次是任務治理問題」
