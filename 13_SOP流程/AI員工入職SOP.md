# AI 員工入職 SOP

## 目的

每一位新的 AI 員工加入 Ewalk.ai Command Center 時，都要先建立入職手冊，明確定義角色、職責、權限、工作流程與交付標準，避免任務分派混亂。

## 使用時機

- 新增一位 AI 員工
- 新增一個專門 Agent，例如行銷助理、設計助理、數據助理
- 現有 AI 員工職責改變
- 某個工作流程準備自動化或半自動化

## 入職資料夾規則

- 通用模板放：`Ewalk.ai Brain/模板/AI員工入職手冊模板.md`
- 各員工手冊放在該員工所屬系統資料夾
- 若還沒有專屬資料夾，先放：`Ewalk.ai Brain/08_自動化/AI員工入職手冊`
- 角色總覽同步更新：`Ewalk.ai Brain/08_自動化/Ewalk.ai AI Command Center.md`

## 必填內容

- 員工定位
- 直屬主管
- 核心職責
- 可以處理的任務
- 不應處理的任務
- 權限範圍
- 工作流程
- 輸出格式
- 品質標準
- 交接規則（含證據/記憶規則：raw artifacts 優先，摘要不得覆蓋證據）
- 常用指令範例

## 執行步驟

### 1. 確認員工定位

先回答：

- 這位員工存在的目的？
- 它負責減少哪一類重複工作？
- 它的產出由誰把關？
- 它是否能直接對外發送、修改、排程或只產出草稿？

### 2. 建立入職手冊

使用 `AI員工入職手冊模板.md` 建立專屬文件。

命名方式：

```text
{{AI員工名稱}}入職手冊.md
```

例如：

- `Gemma入職手冊.md`
- `行銷助理入職手冊.md`
- `數據助理入職手冊.md`

### 3. 設定權限邊界

至少要分清楚：

- 可以自動做
- 可以先做草稿，但要阿順確認
- 需要使用者確認
- 完全不應處理

### 4. 更新 Command Center

在 `Ewalk.ai AI Command Center.md` 補上：

- 角色名稱
- 任務範圍
- 入職手冊連結
- 目前狀態

### 5. 測試第一個任務

每位員工入職後，先給一個低風險測試任務：

- 摘要一份筆記
- 整理一則待辦
- 將一段文字歸檔
- 產出一份草稿

確認輸出符合手冊後，再進入正式分派。

## 驗收標準

- 已建立專屬入職手冊
- 已更新 Command Center 角色總覽
- 權限邊界清楚
- 至少有一個可直接複製使用的指令範例
- 有明確交接規則，知道何時交給阿順或使用者
