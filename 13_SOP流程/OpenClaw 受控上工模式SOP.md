# OpenClaw 受控上工模式 SOP

## 用途

讓 OpenClaw 從純文字測試進入可用產能：可讀指定資料、可寫草稿、可產生本機 action queue，但不直接做外部副作用。

## 啟用條件

需完成：

- B26：Command Center 決策 dry-run 通過。
- B27：限定草稿區寫入通過。
- B28：正式 Brain 指定資料夾 read-only 通過。

三關都通過後，OpenClaw 可進入受控上工模式。

## 可直接做

- 讀取指定 Brain 資料夾。
- 整理客戶現況與上工單。
- 整理社群內容佇列與文案草稿。
- 整理廣告主軸、CTA、上線前缺口。
- 產出 SOP / Prompt 草稿。
- 產出每日交接與待辦回填草稿。
- 將下一步整理成本機 action queue 草稿。

## 讀取範圍

只允許：

```text
01_客戶
02_內容
03_廣告
13_SOP流程
14_每日工作
```

## 寫入範圍

只允許：

```text
00_收件匣/OpenClaw草稿
14_每日工作/OpenClaw草稿回填
08_自動化/openclaw/action-queue
```

所有寫入都必須標示：

- `draft`
- `待審`
- `未批准發布`

## 禁止事項

- 不讀完整 Brain。
- 不讀接案碟。
- 不讀 `.git`、`.obsidian`、secret、token、API key。
- 不寫正式客戶文件。
- 不直接 commit / push。
- 不發文、不排程、不部署。
- 不寫 production Firebase。
- 不接正式客戶通道。
- 不操作廣告預算、金流、帳務或付款設定。

## 外部副作用處理

若 OpenClaw 判斷下一步涉及外部副作用，只能：

1. 產生草稿。
2. 產生 approval queue / action queue 草稿。
3. 標示需提姆先生批准。
4. 交給 Codex 主窗口或 Command Center。

不得自行執行。

## 上工後第一批任務

優先消化提姆先生累積工作：

1. 嘉昱隔熱膜：上線前缺口、LINE 承接、廣告主軸與文案草稿。
2. 韓食日常鍋物：內容佇列、貼文草稿、審稿清單。
3. 每日工作：把三天重建與驗證整理成交接。
4. SOP / Prompt：整理 OpenClaw 實務上工規則。

## 失敗處理

若 OpenClaw 出現以下任一情況，立即停止該任務：

- 讀取未允許路徑。
- 寫入未允許路徑。
- 宣稱已發文、部署或寫 production。
- 自行接正式客戶通道。
- 自行操作廣告或金流。

處理方式：

1. 停止上工。
2. 將事件回填至每日工作。
3. 收緊 allowlist 或交辦文字。
4. 由提姆先生決定是否恢復。
