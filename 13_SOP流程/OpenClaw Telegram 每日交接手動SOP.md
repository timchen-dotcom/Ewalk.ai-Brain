# OpenClaw Telegram 每日交接手動 SOP

## 目的

讓提姆先生可以在 Telegram DM 中，把每日工作紀錄人工貼給 OpenClaw，取得穩定的純文字交接，供隔天回看或由阿順人工貼回 Obsidian。

此 SOP 只定義低風險純文字整理流程，不代表批准讀檔、寫檔、Command Center、正式自動化或任何外部副作用。

## 使用時機

- 每天收工前，需要整理今日完成、未完成、明日優先與風險事項時。
- 提姆先生在手機上想快速把零散工作收成可讀交接時。
- OpenClaw Telegram DM 已可用，但不應讀正式 Brain 或接案碟時。
- 需要先用手動流程驗證每日交接格式，再評估是否升級成更正式流程時。

## 權限邊界

目前允許：

- 依人工貼入文字做摘要。
- 依人工貼入文字做分類。
- 整理待辦與明日優先。
- 標出需提姆先生批准事項。
- 標出禁止事項與高風險操作。
- 產出 Telegram 原生純文字交接。

目前禁止：

- 讀正式 Ewalk.ai Brain。
- 讀 `/Volumes/提姆接案碟`。
- 使用工具、`exec`、搜尋或讀檔工具。
- 寫入或修改任何檔案。
- 自動貼回 Obsidian。
- 接 Command Center。
- 接正式客戶通道。
- 發文、部署、寫 Firebase。
- 操作廣告預算、金流或帳務。

## 每日輸入模板

提姆先生在 Telegram DM 貼：

```text
請整理成每日交接純文字。

今日工作紀錄：
- 今天完成：
- 還沒完成：
- 明天最重要：
- 需要提姆先生批准：
- 風險或不能做的事：

請使用：
【今日結論】
【今日完成】
【未完成與明日優先】
【風險與禁止】
【需要提姆先生批准】
【交接給阿順】

待辦用 TODO：
批准用 APPROVAL：
禁止用 BLOCKED：
```

## 輸出格式

OpenClaw 應只輸出以下六段：

```text
【今日結論】

【今日完成】

【未完成與明日優先】

【風險與禁止】

【需要提姆先生批准】

【交接給阿順】
```

格式規則：

- 使用 Telegram 原生純文字。
- 不依賴 Markdown heading、checkbox、表格或 code block。
- 待辦使用 `TODO：`。
- 需批准事項使用 `APPROVAL：`。
- 禁止事項使用 `BLOCKED：`。
- 不新增提姆先生未貼入的事實。
- 資訊不足時，必須明確要求補齊，不可推測。

## 操作步驟

1. 提姆先生把今日工作紀錄填入每日輸入模板。
2. 貼到 OpenClaw Telegram DM 測試 bot。
3. 檢查 OpenClaw 是否只輸出六段純文字。
4. 檢查是否有 `TODO：`、`APPROVAL：`、`BLOCKED：`。
5. 檢查是否有亂編事實、宣告讀檔、宣告工具可用或承諾外部動作。
6. 若內容可用，由提姆先生或阿順人工貼回 Obsidian 每日工作筆記。
7. 若內容不足，補貼更完整的今日工作紀錄後重跑。

## 驗收標準

每日交接可用的標準：

- 能看出今天最大的結論。
- 能列出今日完成事項。
- 能列出未完成與明日優先。
- 能標出禁止事項與高風險邊界。
- 能標出需要提姆先生批准的事項。
- 能交接給阿順下一步如何接續。
- 沒有聲稱已讀檔、已寫入、已搜尋、已接系統或已執行外部動作。

不通過的情況：

- 自行補出未提供的事實。
- 宣稱已讀取 Obsidian、GitHub、接案碟或正式系統。
- 宣稱可以自動寫回 Obsidian。
- 要求或暗示可以使用 `exec`、工具、搜尋、讀檔。
- 把 Command Center、讀檔工具、寫入流程或正式自動化當成已批准。

## 空白輸入處理

若提姆先生只貼空白欄位，OpenClaw 必須：

- 說明目前只有欄位，缺少實際內容。
- 不整理出不存在的完成事項。
- 用 `TODO：` 要求補齊內容。
- 用 `BLOCKED：` 提醒未填明前不應推測限制。
- 用 `APPROVAL：` 提醒未列明前不應假設已有批准。

## 升級閘門

以下任何升級都需要提姆先生另行批准：

- Command Center 測試。
- 任何讀檔工具測試。
- 任何寫入 Obsidian 或修改檔案。
- 任何工具、`exec`、搜尋或網路使用。
- 任何正式客戶通道連接。
- 任何正式發文、部署、Firebase 寫入。
- 任何廣告預算、金流或帳務操作。
