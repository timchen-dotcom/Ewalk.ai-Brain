# 客戶社群更新頻率追蹤 SOP

建立日期：2026-06-02
主管：阿順
負責職員：成效追蹤員
最終決策者：提姆先生
狀態：MVP 已建立，待正式客戶設定與 Meta API 授權

## 目的

建立一套可重複執行的追蹤流程，確認客戶 IG / FB 是否持續更新，並把「應發幾篇、已發幾篇、還差幾篇」轉成週報、月報與提醒。

## 使用時機

- 客戶有社群代營運或顧問服務
- 客戶或髮型師需要固定每週發文
- 客戶月報要檢查內容更新穩定度
- 阿順要追蹤社群主編、客戶素材提供與自動發文是否有斷點

## 權責分工

| 角色 | 負責 |
| --- | --- |
| 阿順 | 啟動追蹤、判斷風險、決定是否提醒提姆先生 |
| 成效追蹤員 | 執行追蹤、產出報告、標記缺口 |
| 社群主編 | 補排內容、提出本週補發建議 |
| 客戶成功經理 | 追客戶素材、補齊帳號授權 |
| 數據分析師 | 月底併入客戶月報 |
| 提姆先生 | 批准對外提醒、合約調整與高風險通知 |

## 標準流程

1. 建立客戶追蹤設定，填入客戶、平台、帳號 ID、每週目標、每月目標。
2. 確認資料來源：Meta API、手動資料或範例 dry-run。
3. 每週固定執行追蹤腳本。
4. 系統計算本週已發、本週缺口、本月至今應發、本月至今缺口、月底仍需篇數。
5. 狀態為「稍微落後」時，交給社群主編補排。
6. 狀態為「嚴重落後」時，阿順列入週會或客戶成功追蹤。
7. 月底把報告併入客戶月報 Flow。

## 狀態判斷

| 狀態 | 條件 | 行動 |
| --- | --- | --- |
| 正常 | 週 / 月缺口皆為 0 | 不提醒 |
| 稍微落後 | 本週或本月至今缺 1 到 2 篇 | 社群主編補排內容 |
| 嚴重落後 | 本週或本月至今缺 3 篇以上 | 阿順追蹤原因並回報 |
| 待授權 | API 權限不足 | 客戶成功經理補授權 |
| 待確認 | 資料不完整 | 先手動補資料 |

```sh
  --output-dir "Ewalk.ai Brain/04_報表/社群更新追蹤"
```

## 驗收標準

- 每個啟用平台都有週 / 月目標。
- 報告能顯示已發、應發、缺口與狀態。
- 缺口項目能被轉成內部待辦。
- token 沒有寫入 Obsidian。
- 月底資料可併入客戶月報。

## 不做的事

- 不自行對外指責客戶未更新。
- 不自行調整合約承諾篇數。
- 不把私人帳號當成穩定 API 來源。
- 不把 Meta token 寫進任何 Markdown 文件。
- 不把追蹤系統和正式發文權限混用。
