# 霖老師線上車庫更新 SOP

建立日期：2026-05-17
狀態：第一版試行
負責角色：阿順

## 目的

把「5 張車輛照片 + 車輛資訊」轉成可公開的線上車庫頁，讓中古車補教名師-霖老師的在庫車能快速、穩定、可追蹤地更新。

## 使用時機

- 新車上架
- 車輛資料修改
- 車輛保留、售出或下架
- Canva 車庫內容要同步到正式網站

## 輸入資料

必要輸入：

- 1 至 5 張車輛照片
- 車型名稱、年份、等級、售價、車色、里程
- 車況重點 3 至 6 點
- 車輛說明
- LINE / 電話是否沿用預設

可選輸入：

- 看車地點
- 排檔、燃料、主要配備
- 保養紀錄
- 是否可貸款 / 試乘

## 作業位置

- 自動化網站包：`Ewalk.ai Brain/01_客戶/中古車補教名師-霖老師/02_網站與系統/lin-garage-automation`
- 車輛資料檔：`data/garage-data.json`
- 車輛照片：`assets/cars/車輛代號/`
- 可公開網站：`dist/index.html`

## 更新流程

1. 收件  
   使用 `車輛資料收件模板.md` 確認照片與資訊是否完整。

2. 建立車輛代號  
   使用英文小寫與連字號，例如 `toyota-altis-2020-white`。

3. 放置照片  
   建立 `assets/cars/車輛代號/`，照片命名為 `01.jpg` 到 `05.jpg`。

4. 更新資料  
   將車輛資料寫入 `data/garage-data.json` 的 `vehicles` 陣列。

5. 產生網站  
   在自動化網站包資料夾執行 `node scripts/build.mjs`，或雙擊 `產生線上車庫.command`。

6. 檢查公開頁  
   開啟 `dist/index.html`，檢查列表、詳情頁、照片、售價、LINE 與電話 CTA。

7. 發布前確認  
   涉及對外公開，需提姆先生確認車況、售價、是否可上架。

## 上架判定規則

- `available`：可以公開，且年份、等級、售價、車色、里程、車況重點、照片來源都已確認。
- `reserved` / `sold`：可以公開顯示狀態，但仍需符合公開必填資料。
- `draft`：資料可以先入庫，但不出現在公開頁。

以下情況一律先用 `draft`，不要硬上架：

- 售價、年份、里程、車色、等級或車況重點任一項是「待確認」。
- 照片不足、照片路徑不確定，或使用 AI 生成外觀圖但尚未確認可公開。
- 認證狀態、事故資訊、鈑件更換說法還沒有提姆先生批准。

## 防重跑停損規則

- 同一台車只做一次資料檢查與一次建置；失敗時列出缺口後停止。
- 不要為了讓建置通過而猜測售價、里程、認證、車況或照片來源。
- 如果資料不足，輸出「先入庫草稿，等待提姆先生補資料」，不要繼續重複寫入或重跑。
- 每次新增車輛前先確認 `id` 是否已存在；已存在就改原資料，不新增第二筆。

## 驗收標準

- [ ] 網站可正常開啟
- [ ] 車輛列表顯示正確
- [ ] 詳情頁最多顯示 5 張照片
- [ ] LINE 與電話 CTA 正確
- [ ] 缺照片、缺公開必填欄位，或公開車含「待確認」時，建置會擋下
- [ ] 不確定資訊沒有被阿順自行腦補
- [ ] 對外發布前已取得提姆先生確認

## 失敗處理

- 圖片找不到：確認圖片是否放在 `assets/cars/車輛代號/`，路徑是否與 JSON 一致。
- 建置失敗：先看錯誤訊息補欄位，不要直接略過檢查。
- 售價或車況不確定：狀態先設為 `draft`，等提姆先生確認後再公開。
- 客戶臨時要求下架：狀態改成 `draft` 後重新建置。
